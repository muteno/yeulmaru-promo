# 역대 기획공연 판매결과 DB 설계 — 260803

> **목적**: 앱에 전무했던 「매출·정산」 축을 신설한다. 앱의 판매·사업 분석은 지금까지 관객수(발권유료)와 점유율뿐이었고,
> 금액은 2025~26 일일입력·전시에만 있었다. 운영자 보관 원본 엑셀(운영 관리대장·티켓판매결과)에서
> **2012~2024 기획공연 262건의 확정 매출·정산**을 뽑아 전용 시트로 반입한다.
> 기존 시트(일일입력/공연마스터/세부운영관리대장(정리)/전시\*)는 **무변경** — 전시 DB(260620) 전례와 동일하게 전용 신설 시트로만.

## 1. 시트 구성

| 시트 | 대응 기존 시트 | 역할 |
|---|---|---|
| **운영_기획공연판매결과** (신설) | 운영_전시마스터 격 | 기획공연 1행 = 1공연(런) **결산 차원** — 매출·공제·순수입·가용석·무료발권 내역 |
| *(조인키 = 공연ID)* | 운영_세부운영관리대장(정리) | 관객·회차·장르는 기존 운영대장이 정본 — 이 시트는 **금액 축만 추가** |

- 행 단위 = **공연(런)**: 같은 해 같은 제목의 별개 런(날짜 상이)은 별도 행(예: 2020 술술클래식 6월/12월, 2023 이상한엄마 11시/14시 블록).
- 조인 = `공연ID`(운영대장 Phase 2 ID, 250/262행) → 실패분은 `공연명`+`년도` 정규화 매칭 폴백.

## 2. 스키마 (35열)

`공연ID · 년도 · 공연명 · 구분 · 사업명 · 장르 · 장소 · 시작일 · 종료일 · 원본날짜 · 일수 · 회차 · 티켓가 ·`
`가용석 · 불용석 · 유료판매석 · 유료비율 · 무료_티켓나눔 · 무료_프로모션 · 무료_기타 · 무료합 · 단체예매수 · 총매수 · 점유율 ·`
`총판매금액 · 공제_수수료 · 공제_기타 · 현금보유분 · 인터파크지급액 · 수입 · 지출 · 지출_공동기획배분 · 순수입 · 출처 · 비고`

- **년도** = 소스 결산 연도(시트)가 정본. 운영대장 조인은 **동년 에디션만**(±1 금지 — 재연 오귀속 방지).
- **시작일/종료일**(YYYYMMDD) = 운영대장(정리) 동년 에디션의 첫/끝 공연일. 미조인 행은 공백(`원본날짜` 원문 참조).
- **가용석** = 원본 「좌석수」(유보석·휠체어·사석·op석·2층 등 **불용석 차감 후** 실오픈석) — 운영대장 「기본좌석」보다 정밀한 점유율 분모.
- **유료비율·점유율** = %(소수1). 원본은 분수(0~1.02, 오버셀 포함) → ×100 저장.
- **정산 구조(원본 실측)**: `수입 = 총판매금액 − 공제_수수료 − 공제_기타` · `인터파크지급액 = 수입 − 현금보유분`(현금판매는 인터파크를 안 거침). 2021 이전 소스의 공제_수수료=인터파크수수료, 공제_기타=SMS발송료.
- **단체예매수** = 2023~ 소스에만 존재(이전 연도 공백).
- **출처** = 어느 원본 시트에서 왔는지 · **비고** = 파서 자동 주석(중복 정리·정산식 불일치 의심·현황판 금액 성격 등).

| 소스 | 채택 구간 | 판정 근거 |

| 티켓판매결과 › (2025)탭 | **제외** | 오라벨 — 제목 「2024년」, 내용 = 2023·24 통합 작업본(소계행 혼입·블록2/3은 총매출 기준 상이). 전 행이 (2023)/(2024)탭과 중복임을 실측 확인, 교차검증용으로만 사용 |
| 2023 공연장 운영관리.xlsx | **제외** | 마스터대장의 구 스냅샷 — 고유 데이터 없음 |

## 4. 병합·조인 규칙 (파서 `docs/260803_sales_hist_parse.py`)

1. **키** = (년도, 정규화 공연명). 정규화 = 운영대장 `_uName` 계승(꺾쇠·구분자·「- 여수」 제거) + 접두 연도·장르어·주최어 반복 제거 + **별칭 34종**(라이브 운영대장 실측 대조로 확정 — 파서 상단 ALIAS, 예: 「국악 무풍」=「연희단팔산대 무풍(舞風)」).
2. **동일소스 중복**: 날짜가 다르면 별개 공연으로 **둘 다 보존**, 같으면 신·구 스냅샷으로 보고 선행 채택(예: 2023 이상한엄마 — 운영대장 6회차·발권 3,750 = 두 행 합(2,022+1,728)과 합치 → 별개 보존이 정답임을 실측).
3. **교차소스 중복**: 정산탭 우선, 현황판은 미보유 공연만 추가. 금액이 2% 이상 다르면 비고에 현황판 값 병기(공동기획 배분차 — 썸데이·노트르담·봄봄·친구의전설 4건).
4. **정산식 자가검증**: `총판매−공제≠수입`(±1000원) 행은 비고 플래그 — 원본 오기 2건 검출(2021 캣츠 28.6만원차, 2024 룰루랄라 총판매 1,004,500 오기 의심 · 수수료 역산 ≈ 10,045,500).
5. **운영대장 조인**: uname → uname2 → 별칭 → 포함 매칭(양쪽 4자 이상·동년·유일 에디션 한정, daily_ingest 길이가드 계승).

## 5. 검증 결과 (260803 실측)

- **262행 · 공연ID 조인 250(95.4%)** · Σ총판매금액 **137.8억 원**(2012~2024).
- 잔여 미조인 12 = 운영대장(정리) 자체에 없는 항목: 여성영화산책 2015·16 상영분 6, 원스어폰어타임 코스모/모던 2, 그린 그림Ⅳ, 패키지티켓, 한중연합(2012), 찾아가는광장영화관 — 비고 표기됨.
- **교차 대사**: 연도별 Σ유료판매석(신규시트) ↔ Σ발권유료(운영대장 조인분) — **2013·2014·2019 정확 일치**, 그 외 연도도 발권·판매 기준차 범위 내.
- 연도별 Σ총판매금액(백만): 2012 314 · 2013 602 · 2014 938 · 2015 1,052 · 2016 990 · 2017 1,142 · 2018 1,145 · 2019 1,624 · 2020 253 · 2021 1,365 · 2022 1,944 · 2023 1,562 · 2024 854(현황판 보충분은 `수입`만 — 총판매 합계엔 미포함).

## 6. 반영 절차

```
# 1) (원본 엑셀 변경 시) 재파싱 — 산출물 = docs/260803_기획공연판매결과.json (기계산출물 · 손편집 금지)
python3 docs/260803_sales_hist_parse.py <원본엑셀폴더>

# 2) 미리보기(시트 무접촉) → 반영(운영_기획공연판매결과 풀라이트 생성/교체)
node docs/260803_sales_hist_ingest.mjs
DB_PW=<슈퍼비번> node docs/260803_sales_hist_ingest.mjs --write
```

- Worker `/api/ops` POST가 시트를 자동 생성/교체(전시 DB 전례) — **재실행 안전(idempotent)**, 다른 시트 무접촉.
- 시트 데이터 수정은 CLAUDE.md 데이터 안전 수칙대로 Worker API 경로만 사용(마스터 xlsm 직접 편집 금지).

## 7. 유지·확장

- **2025+ 결산**: 연 1회, 해당 연도 판매내역 탭 확정 후 파서에 소스 추가(parse_d 1줄) → 재실행 → `--write`.
  2025~26 진행분 매출은 기존 일일입력(판매금액)이 실시간 담당 — 이 시트는 **결산 아카이브**로 역할 분리.
- **앱 소비(Phase 2 — 별도 작업)**: `/api/ops?sheet=기획공연판매결과` 지연 로딩 →
  ① 대시보드 ▸ 사업 결과 비교에 매출 축(연×장르 총판매금액·순수입) ② 판매현황 드릴에 동장르 역대 매출 벤치마크
  ③ 수익성 휴리스틱(`_profitType`)을 실측 대체(지출_공동기획배분>0 = 공동기획 등) ④ 가용석 기반 점유율 정밀화.
- **원본 오기 2건**(§4-4)은 운영자 원본 수정 대상 — 수정 후 재파싱하면 플래그 자동 소멸.
