5. 실측에서 잡힌 것 — 변경 착수 전 알고 갈 것

① QA 딥링크 8개 중 #bizstatus 하나만 아무것도 안 연다 — 8개 전부 [QA] deep-link → … 로그는 찍히는데, 착지 결과가 갈린다. 하필 【레포 바인딩】이 대표 딥링크로 등재해 둔 「사업 현황」이 그 하나다. nav 버튼을 앱이 자리잡은 뒤 직접 누르면 보드는 정상으로 열린다 = 딥링크가 너무 이른 시점에 click을 쏘고, openYearBoard()가 조용히 아무것도 안 하고 끝난다. 근거: 8개 딥링크 각각 새 페이지 로드 후 9초 실측 — biz/cal = 메인 전환 ✅ · prodreg = 모달 1개 ✅ · promoapply·sales·content·playzone = dd-pop ✅ · bizstatus = 모달 0 · dd-pop 없음 ❌. 추가로 t=3/6/10/15s 4회 재확인도 전부 0개.
② 좌·우 KPI 헤더가 통째로 중복 — 「연간 실적 / 2012~2026.1Q / 누적 3,690,031명」 + KPI 4칸이 화면에 두 번 나온다(좌 #biz-main, 우 #rail-yrm). 260724 이식 1단계의 잔재. 근거: PC 1440 렌더 스샷 — 같은 숫자 4개가 좌우에 나란히.
③ 모바일 390px에서 KPI 스트립이 깨진다 — 라벨이 「누게 …」 「최고 …」 「전년 …」으로 잘리고, 1,505,706과 158,259가 서로 붙어버린다. 근거: 390×844 렌더 스샷. 4칸을 한 줄에 밀어넣어서 생긴 오버플로.
④ 차트 빈 통은 정상 — #yrm-chart 410px가 비어 보이는 건 QA 모드에서 실API를 차단해 데이터가 0이기 때문. 버그 아님. 근거: 콘솔 [QA] api intercepted (no real network) 다수.
