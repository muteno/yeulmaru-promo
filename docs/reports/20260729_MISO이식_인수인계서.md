## 3. 실측 확정 사실 — **재조사 불필요**

### A. iframe 임베드 가능성 ✅ 확인됨

| 항목 | 실측 결과 |
|---|---|
| `promo.yeulmaru.org` 응답 헤더의 `X-Frame-Options` / CSP `frame-ancestors` | **없음** → 임베드 차단 안 됨 |
| cross-origin iframe 실제 렌더 | **정상** — 내비 12개 · 카드 4개 · `body.innerHTML` 1,614,878자 |
| iframe 안 `localStorage` | **접근 가능** |
| iframe 안 `serviceWorker` | **사용 가능** |
| 모바일 가드(`#mobile-guard`) 오작동 | **없음** — 260610에 이미 차단 해제(`display:none` 유지) |
| iframe 안 JS 에러 | **0** |

### B. 디자인 — 폭이 전부다 ✅ 원인 규명 완료

「디자인이 안 완벽하다」의 정체는 **앱 결함이 아니라 iframe 폭 부족**이다. 폭별 내비 요소 겹침 실측:

| 뷰포트 폭 | 겹침 쌍 | 비고 |
|---|---|---|
| 1920 / 1600 / **1440** | **0** | 깨끗 |
| 1280 | 1 | 가로 스크롤 발생 |
| 1206 | 2 | 가로 스크롤 발생 (첫 시연 스샷이 이 폭) |
| 1100 | 3 | |
| 1024 | 4 | |
| 900 | 5 | |

겹치는 조합은 월 이동 화살표(`‹` `›`)와 내비 항목(`대시보드`·`캘린더`). **1440px 이상이면 앱 수정 없이 완벽하다.**

### C. 데이터 경로 — `?qa=1`은 쓸 수 없다 ⚠ 중요

`index.html`의 `api()` 함수(약 L3657):

```js
async function api(method,path,body){
  if(window._QA)return _qaApi(method,path,body);   // [QA] 실네트워크 차단 — 목데이터만
  const headers={'Content-Type':'application/json','X-App-Password':password};
  ...
}
```

- `?qa=1`은 **설계상 실네트워크를 차단하고 목데이터만 반환**한다. 요구 5(데이터 다 들어가야 함)와 **양립 불가**. 재활용 금지.
- 실데이터 경로는 **`X-App-Password` 헤더 하나**로 열린다. **MSAL 토큰은 Worker 호출에 쓰이지 않는다** → 로그인을 제거해도 데이터는 나온다.
- Worker 검증(`src/index.js` L44~48): `roleOf(pw, env)` — `APP_PASSWORD`면 `user`, `ADMIN_PASSWORD`면 `admin`.

### D. `0510`은 이미 소스에 평문으로 있다 ⚠ 보안 현황

- `index.html`에 `password='0510'` **6곳**, 라이브 배포본 문자열 기준 **9곳**.
- 출처는 `goToPinStep()` — 담당자 목록(`loadManagers()`)을 PIN 입력 **전에** 불러오기 위해 임시로 세팅한다.
- **따라서 요구 4(0510 단일 게이트)는 보안 수준을 새로 낮추는 게 아니라, 이미 노출돼 있는 상태를 UI에 반영하는 쪽에 가깝다.** 다만 **「주소 + 0510을 아는 사람은 사외에서도 접근 가능」이라는 성질은 그대로 남는다** — 이 점은 운영자가 인지한 상태에서 진행하기로 한 결정이다.

### E. MSAL 현황 (제거 대상)

| 항목 | 값 |
|---|---|
| 로그인 호출 | `loginPopup` 4곳 · `loginRedirect` 4곳 · `acquireTokenSilent` 5곳 |
| 캐시 | `cacheLocation: 'localStorage'` |
| 상태 저장 | `storeAuthStateInCookie: true` |

iframe 안에서 이 셋은 각각 **스토리지 파티셔닝 · 서드파티 쿠키 차단 · MS 로그인 페이지의 iframe 표시 거부**에 걸린다. **즉 로그인 제거는 선택이 아니라 iframe 방식의 전제조건이다.**

### F. 로그인 흐름 구조 (건드릴 지점)

| 함수 | 위치 | 역할 |
|---|---|---|
| `initLoginScreen()` | L3386 | `account-step` 표시 → `_msalGetEmailSilent()`로 계정 확인 |
| `goToPinStep(skipEnsure)` | L3468 | `_msalEnsureToken()` 검증 → `MANAGERS` 로드 → `pin-step` 표시 |
| `_enterApp()` | L3138 | 앱 본화면 진입 |
| `_enterAppFromSession()` | L3595 | `password=sessionStorage.getItem('pw')` 복원 후 **로그인 화면 없이 직행** |
| 세션복원 IIFE | L3603 부근 | `window._QA`면 `_qaEnter()`, 아니면 `pw` 유무로 분기 |
| `startLoginShader()` | L3292 | 로그인 배경 셰이더(디자인) — **유지 대상** |

**`_enterAppFromSession()`이 이미 「password만 있으면 로그인 없이 진입」 경로다.** 새 모드는 이 경로를 재사용하면 되고, 새 라우팅을 창작할 필요가 없다(B1 레퍼런스 = 이 함수).

### G. 로그인 제거 시 죽는 기능 (MS Graph 의존)

MSAL 토큰이 없으면 아래 7개 엔드포인트를 쓰는 기능이 동작하지 않는다. **UI에서 숨기거나 안내로 대체해야 한다**(에러 토스트가 뜨면 「데이터가 다 안 들어온다」는 인상을 준다).

```

graph.microsoft.com/v1.0/me/drive/sharedWithMe    (공유받은 폴더)

graph.microsoft.com/v1.0/sites                    (사이트 검색)
graph.microsoft.com/v1.0/sites/                   (사이트 드라이브)
```

관련 코드 위치 = `_msalPrefetch()`(L14828 부근) 및 L14855~15000 구간. 필요 권한 주석 = L2415(`Files.Read.All` / `Sites.Read.All`).

## 4. 구현 설계안 (권장)

> 원칙: **기존 함수 재사용, 새 라우팅·새 토큰·새 색 창작 0.** CLAUDE.md B1 준수.

### 4-1. 진입 경로

새 쿼리 파라미터(예 `?embed=1`)로 아래 흐름을 탄다. **기존 로그인 흐름은 무변경으로 남긴다**(QA 모드가 `?qa=1`로 공존하는 것과 동일 패턴).

```
?embed=1
  → startLoginShader()            // 디자인 그대로 유지
  → account-step 건너뜀            // MSAL 전부 우회 (_msalGetEmailSilent · _msalEnsureToken 호출 안 함)
  → pin-step 즉시 표시             // 요구 4 "첨에 핀값 입력하는 곳부터"
  → 입력값 === '0510'
       → password='0510'; userRole='user'
       → sessionStorage.setItem('pw','0510')
       → _enterAppFromSession()   // 기존 경로 재사용 (L3595)
  → 이후 api() 호출은 실데이터 (요구 5 충족)
```

### 4-2. 같이 처리해야 할 것

| 항목 | 처리 |
|---|---|
| MS Graph 의존 UI (§3-G) | embed 모드에서 **숨김 또는 비활성 + 안내 1줄**. 에러 토스트가 뜨지 않게 하는 게 핵심 |
| 자동 잠금 | `IDLE_MS = 30*60*1000`(L3600). iframe에 띄워둔 화면이 30분 뒤 잠기면 시연 중 사고 → embed 모드에서 **잠금 비활성 검토** |
| `MANAGERS` 로드 | `goToPinStep`이 담당자 목록을 미리 불러오는데, embed 경로는 이 단계를 건너뛰므로 **진입 후 로드되는지 확인** 필요 |
| 서비스워커 | 260729e에 도입됨. HTML은 네트워크 우선이라 embed 모드와 충돌 없음. iframe 안에서도 등록 가능(실측 §3-A) |

### 4-3. 폭 대응 (MISO 화면 보고 택1)

- **1440px 이상 확보되면** → 아무것도 안 해도 된다(§3-B).
- **안 되면** → iframe을 1440 고정 + `transform: scale()` 축소. **앱 코드 수정 0**:

```html
<div style="width:100%;overflow:hidden">
  <iframe src="https://promo.yeulmaru.org/?embed=1"
          style="width:1440px;height:900px;border:0;transform:scale(.84);transform-origin:0 0"></iframe>
</div>
```
(`.84` = 실제 칸 폭 ÷ 1440. 칸 폭이 1210이면 1210/1440 ≈ 0.84)

## 5. 검증 방법 — 재현 자산

### 5-1. ⚠ 로컬 서버는 반드시 HTTPS

`index.html` **L6**에 HTTP→HTTPS 승격 스크립트가 있어 **`http://` 로컬 서버로는 렌더 자체가 안 된다**(`ERR_SSL_PROTOCOL_ERROR`). 자가서명 인증서로 HTTPS 서버를 띄울 것. 서비스워커도 secure context가 필요하므로 어차피 HTTPS여야 한다.

```bash
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 30 -nodes \
  -subj "/CN=127.0.0.1" -addext "subjectAltName=IP:127.0.0.1,DNS:localhost"
```

### 5-2. cross-origin iframe 재현 (실제 임베드 상황)

**포트를 다르게 해야 진짜 cross-origin이 된다.** 8443 = 레포(앱), 8444 = 포털 모의 페이지.

```html
<!-- 8444에서 서빙 · 8443 앱을 임베드 -->
<div class="bar"><b>MISO</b> 사내 포털 (모의)</div>
<div class="side">메뉴 / 홈 / 앱 / 예울마루 대시보드</div>
<div class="wrap"><iframe src="https://127.0.0.1:8443/?embed=1"></iframe></div>
```

Playwright 실행 시 필수 인자: `--no-proxy-server` · `--ignore-certificate-errors`, 컨텍스트에 `ignoreHTTPSErrors: true`.
브라우저 실행 경로 = `/opt/pw-browsers/chromium`.

### 5-3. 폭별 겹침 자동 측정

```js
const items=[...document.querySelectorAll('nav a,nav button,[data-mid]')].filter(e=>e.offsetParent);
let overlap=0;
for(let i=0;i<items.length;i++)for(let j=i+1;j<items.length;j++){
  const a=items[i].getBoundingClientRect(), c=items[j].getBoundingClientRect();
  if(a.left<c.right&&c.left<a.right&&a.top<c.bottom&&c.top<a.bottom) overlap++;
}
```
1920/1600/1440/1280/1206/1100/1024/900 순회하며 `overlap`을 찍으면 §3-B 표가 재현된다.

### 5-4. ⚠ 세션 환경 제약 (헛수고 방지)

- **헤드리스 브라우저로 라이브(`promo.yeulmaru.org`)에 접속하면 프록시가 연결을 리셋한다**(`ERR_CONNECTION_RESET`). `curl`은 프록시를 통해 정상 동작한다. **라이브 검증은 curl로, 렌더 검증은 로컬 HTTPS 서버로** 나눠서 할 것.
- 로컬 서버는 Bash 툴의 `nohup ... &`로 띄우면 호출 종료 시 죽는다. **`run_in_background: true`로 띄울 것.**
- `pkill -f serve.py`는 자기 자신(명령줄에 문자열 포함)을 죽여 Exit 144를 낸다. 포트 확인으로 대체.
