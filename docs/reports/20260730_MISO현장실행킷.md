> 작성 2026-07-30 KST · 선행 문서 = `docs/reports/20260729_MISO이식_인수인계서.md`(Q.25 — 조사·실측 전량)
> **용도**: 내부망에서 MISO 화면을 띄운 상태로 **이 문서 하나만 열고** 그대로 실행한다.

> 전달 방식 = 복붙. 아래 블록들이 전달물의 전부다.

## 1. 첫 5분 — MISO 화면에서 3가지만 확인 (분기 결정)

| # | 확인 | 있으면 |
|---|---|---|
| ① | 외부 URL을 **iframe**으로 박을 자리(임베드 위젯·HTML 블록) | → **분기 A** (최단 경로) |
| ② | 없으면: **v0(바이브) GUI로 커스텀 페이지** 생성 가능 | → **분기 B** (v0로 래퍼 생성) |
| ③ | 워크플로 **HTTP 노드가 사외 도메인**(`*.workers.dev`) 호출 가능 | → **분기 C 실데이터 모드** 가능 |

셋 다 안 되면 → **분기 D**: 새 탭 링크(바로가기)만 등록 — 현재 앱 그대로, 작업 0 (Q.25 §2-2).
①~③은 서로 배타가 아니다 — **A/B(화면) + C(데이터·자동화)를 병행**하는 게 완성형.

## 2. 분기 A·B — 화면 반입 (iframe / v0 래퍼)

**전제(레포 쪽 선행 작업)**: `?embed=1` 진입 경로(MSAL 우회 → PIN 첫 화면 → `0510` 통과 → 실데이터)는
Q.25 §4에 설계 확정, **아직 미구현**. 구현 전까지는 `?qa=1`(목데이터 데모)로 화면만 보여줄 수 있다.
→ 화면 확인 후 "embed 모드 구현 시작"이라고 지시하면 이 레포에서 바로 구현한다(§6).

### A. iframe 자리가 있을 때 — 붙여넣기 (Q.25 §4-3 원본)

```html
<div style="width:100%;overflow:hidden">
  <iframe src="https://promo.yeulmaru.org/?embed=1"
          style="width:1440px;height:900px;border:0;transform:scale(.84);transform-origin:0 0"></iframe>
</div>
```
- 칸 폭이 **1440px 이상**이면 `transform` 두 속성을 지우고 `width:100%`로. (1440 이상 = 겹침 0 실측)
- `.84` = 실제 칸 폭 ÷ 1440 (예: 1210px 칸 → 1210/1440 ≈ `.84`)
- embed 구현 전 데모는 `src="https://promo.yeulmaru.org/?qa=1"` (목데이터·무로그인)

### B. v0(바이브) GUI로 래퍼를 만들어야 할 때 — 채팅에 붙여넣기

```
예울마루 사업 대시보드를 담는 임베드 페이지를 만들어줘.
- 페이지 전체를 차지하는 iframe 하나: src = https://promo.yeulmaru.org/?embed=1
- iframe은 width 1440px 고정, height는 뷰포트 100%, border 없음
- 컨테이너 폭이 1440px보다 좁으면 transform: scale(컨테이너폭/1440)로 축소하고
  transform-origin은 좌상단, 컨테이너는 overflow hidden
- 배경색 #FDF6F3, 다른 UI 요소는 넣지 마
```

### 확인 체크리스트 (A·B 공통)

- [ ] 내비 겹침 없음 (1440 미만이면 scale 적용됐는지)
- [ ] PIN 화면이 첫 화면으로 뜸 → `0510` 통과 (embed 구현 후)
- [ ] 캘린더에 실데이터 로드됨 — 안 되면 사내망이 `workers.dev`를 차단하는 것 (Q.25 R3) → §3-B 스냅샷 경로로 전환
- [ ] 차트 렌더 — 깨지면 CDN(jsdelivr·plotly) 차단 → 레포에 벤더링 필요(우리쪽 작업, §6)

## 3. 분기 C — 에이전트·워크플로 (데이터 반입)

### 3-A. 데이터 번들 (이 레포가 만들어 놓은 것)

| 산출물 | 내용 | 용도 |
|---|---|---|
| `data/miso_db.json` | 전 데이터셋 단일 JSON `{meta, datasets:{이름:{headers,rows}}}` | 워크플로 코드 노드·v0 앱 |
| `data/miso_kb/*.csv` | 데이터셋별 CSV (**PIN·비밀번호·이메일 마스킹 완료**) | **에이전트 지식베이스 업로드** |

현재 등재(SharePoint 시트는 내보내기 반입 대기 — `data/db_export/README.md` 절차):

| 데이터셋 | 행 | 내용 |
|---|---|---|
| `exhib_master` | 25 | 전시 마스터(전시ID·기간·목표·최종실적·수익성) |
| `exhib_daily` | 937 | 전시 일일실적(기준일자·유무료·누계·점유율) |
| `edu_institutions` | 499 | 유치원·어린이집 지도 마커(여수·순천·광양, 좌표) |
| `edu_roster` | 499 | 교육기관 원천 명단(주소·우편번호) |

다운로드 URL(내부망): `https://promo.yeulmaru.org/data/miso_kb/<데이터셋>.csv`
갱신 명령(레포 쪽): `npm run build:misodb` — SharePoint 내보내기 CSV를 넣으면 8시트(신청내역·프로그램·담당자
등)도 자동 합류. **회원 DB는 데이터 미반입·구조만 설계 등재**(§5).

### 3-B. 에이전트 앱 — 시스템 프롬프트 붙여넣기

지식베이스에 §3-A CSV들을 올린 뒤:

```
너는 "예울마루 데이터 도우미"다. GS칼텍스 예울마루(여수 문화예술공원)의 공연·전시·교육
사업 데이터를 근거로만 답한다. 지식베이스에 없는 값은 "데이터에 없음"이라고 답하고 추측하지 않는다.

데이터 사전:
- exhib_master(전시 마스터): 전시ID(YYMMDD_NN)·전시명·연도·시작일·종료일·운영일수·목표관객·
  목표금액·최종유료/무료/총인원/매출·최종점유율·수익성·상태. ⚠️ 점유율 = 목표 달성률(100% 초과 가능),
  좌석 점유율 아님. 수익성 = 참고용 초안 값.
- exhib_daily(전시 일일): 기준일자(YYYYMMDD)·전시ID·일일 유료/무료/총인원/금액·누계 4종·점유율.
  전시ID로 exhib_master와 조인.
- edu_institutions / edu_roster: 여수·순천·광양 유치원·어린이집 (단체 관람 영업 대상).
  src='approx-city'인 행의 좌표는 시 중심 근사값이라 위치 판단에 쓰지 않는다.
- (반입 시) records=홍보 신청내역, programs=공연 프로그램, managers=담당자(민감정보 마스킹됨),
  platforms=홍보 플랫폼, special=담당자 특별일정, applysettings=접수 설정.

답변 규칙: 한국어. 수치는 근거 행을 함께 제시. 기간 질문은 시작일~종료일로 판단.
```

### 3-C. 워크플로 앱 — 실데이터가 필요할 때 (HTTP 노드 → 기존 Worker API)

§1-③이 가능하면 스냅샷 대신 **라이브 데이터**를 쓴다. CORS 전면 개방(`ALLOWED_ORIGIN=*`)이라 즉시 호출 가능:

```
베이스 URL: https://yeulmaru-promo-api.yeulmarumaster.workers.dev
공통 헤더: X-App-Password: <앱 비밀번호 — 운영자가 아는 4자리>

읽기(핵심 5개):
  GET /api/records                → {records:[{...홍보기록 헤더, _rowIndex}]}
  GET /api/programs               → {programs:[{...프로그램 헤더}]}
  GET /api/sheet/<slug>           → {headers:[...], rows:[{..., _rowIndex}]}
      slug = platform|content|manager|program|special|applysettings (log는 admin 전용)
  GET /api/ops?sheet=전시마스터    → {headers, rows} (운영_ 시트, 전시일일도 동일)
  GET /api/holidays?year=2026     → {days:[{date,name}]} (공휴일)
쓰기: POST/PATCH/DELETE도 있으나(관리자 헤더 필요) 1단계에선 읽기만 권장.
상태: GET /api/health → {status:'ok'}
```

### 3-D. MISO 라이선스 키 치환표 — 앱의 AI 기능이 쓰는 키

운영자 방침: 외부 AI 키는 **MISO 사내 라이선스 키로 대체**. 현재 앱의 AI 기능과 키 매핑:

| 앱 기능 | 현재 키(Cloudflare Worker 시크릿) | MISO 이식 시 |
|---|---|---|
| 블로그 초안 생성(`/api/content/blog`) | `GEMINI_API_KEY`(우선) 또는 `ANTHROPIC_API_KEY`(기본 모델 claude-opus-5) | **MISO LLM 노드**(사내 Opus)로 재구현 — 키 입력만 하면 됨. 프롬프트 계약은 Worker `generateBlogDraft` 참조(주제·의도·타겟·팩트·템플릿·길이·어조·이모지) |
| 홍보물 이미지 정보 추출(`/api/content/ocr`) | Gemini Vision → Google Vision → CLOVA 순 폴백 | MISO 멀티모달/비전 노드 1개로 통합 |
| 텍스트→구조화(`/api/content/structure`) | 위 LLM과 동일 | MISO LLM 노드(JSON 출력) |
| 블로그 장문 파이프라인(GitHub Actions `nb-blog`) | `CLAUDE_CODE_OAUTH_TOKEN_*` 5계정 페일오버 | MISO 워크플로로 대체 가능(장문 생성 노드) — 대체 전까지 기존 경로 유지 |
| 공휴일(`/api/holidays`) | `KASI_KEY`(공공데이터) | AI 아님 — 유지 or 스냅샷 |
| 지도(홍보 지도) | Naver Maps `ncpKeyId`(프론트 공개키) | AI 아님 — 유지 |

**치환 원리**: 위 기능들은 전부 "입력 → LLM → 출력" 구조라서, MISO 워크플로에서 같은 프롬프트로
노드만 구성하면 키는 플랫폼(회사 라이선스)이 자동 공급한다. 앱 쪽 코드는 그대로 두고
**MISO 안에서 병렬 기능으로 재구현**하는 것이 1단계 — 앱의 해당 버튼을 MISO로 돌리는 건 2단계.

## 5. 회원 DB — 내일 반입분 사전 설계

- 파일명에 `회원`이 들어간 파일(CSV/JSON/xlsx 변환분)은 빌더가 **데이터를 반입하지 않고**
  구조(헤더·행수)만 `data/miso_db.json` → `meta.memberSchema`에 등재한다(공개 레포 PII 차단).
- 참고 실계약: Worker의 `운영_회원` 처리도 **A~G 7열 + 파생 연령대만** 외부 노출(개인정보 최소화) —
  MISO 반입도 같은 원칙 권장: **연령대·지역 등 파생·집계본만** 지식베이스에 올리고 원본(이름·연락처)은 올리지 않는다.
- 파일이 오면: `node tools/miso/build_db.mjs` 실행 → `meta.memberSchema` 실측 확인 → 마스킹 규칙(어느 컬럼을
  파생·집계로 바꿀지) 운영자와 확정 → 전용 마스킹 추가 후 반입. 실데이터가 필요하면 `--include-members`
  (산출물 **커밋 금지**, MISO 업로드 전용).
