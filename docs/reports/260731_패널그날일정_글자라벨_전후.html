260731 — 날짜 패널 「그날 일정」: 구분 = 알약 폐지·글자만 + 3열 잉크 수평 실측

운영자 3차 지시: "저 공연 버튼은 없애줘. 그냥 글자로 표현. / 각 글자가 광학 잉크 렌즈로 가로 수평을 맞춰주나 봐봐"

전후

전 — 알약(버튼) 라벨
후 — 글자만(색으로 구분) · 세 열이 같은 기준선

조치

구간내용
.panel-hdr-kind배경·패딩·라운드 전부 제거 → 글자만. 형태는 같은 패널의 정본 부품 .sp-card-type(12.5px/700, 색만 다른 글자 라벨) 계승. 색은 종전 그대로 캘린더 셀과 공유(perfBadgeBg() — 기획 --accent / 대관·셋업 --neutral-text), 인라인 background → color
.panel-hdr-labelsalign-items:center → baseline. 열마다 글자 크기가 달라(12.5 · 13 · 11px) 박스 중앙 정렬은 글리프가 어긋난다 — 기준선을 공유시켜 「같은 줄 위에 앉은」 상태로

광학 잉크 실측 — tools/scratch/probe_panel_ink.mjs

글자 박스가 아니라 글리프 잉크를 잰다. 각 열 텍스트의 baseline = Range 상단 + fontBoundingBoxAscent, 잉크 상·하단 = canvas TextMetrics.actualBoundingBoxAscent/Descent. 기준 = 2열(제목), 값 = [1열 구분, 3열 장소]의 편차. 5행 전건 측정.

정렬 모드baseline 최대 Δ잉크중심 최대 Δ잉크하단 최대 Δ판정
align-items:center (구판)0.5000.5001.500행마다 세 글자가 서로 다른 기준선 — 「수평이 안 맞는」 상태
align-items:baseline (적용)0.0000.5001.000기준선 완전 일치 (5행 × 2열 전건 0.000)

· 잉크중심·잉크하단의 잔여 Δ는 글자 크기가 다르면 물리적으로 남는 몫이다(13px 제목이 11px 장소보다 위아래로 더 크다). 한글은 디센더가 없어 기준선 일치 = 눈에 보이는 수평 일치이므로 baseline이 정답.
· baseline Δ 0.000은 폰트에 의존하지 않는 레이아웃 규칙의 결과(격자 항목의 기준선 공유)라 실측 환경(오프라인 = Pretendard 미로딩·폴백 폰트)과 무관하게 유지된다. 잉크중심/하단 수치만 폰트 의존 — 0.5px 단위로 양자화된 것도 폴백 폰트 메트릭 탓.
· 억지 translateY 광학보정은 쓰지 않았다 — 기준선 공유만으로 0.000이 나오므로 하드코딩 보정값이 필요 없다(값이 굳으면 폰트·크기 변경 때 드리프트 원인).
