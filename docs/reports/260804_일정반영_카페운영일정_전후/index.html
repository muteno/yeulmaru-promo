260804 관리 ▸ 일정 반영 ▸ 카페 운영 일정

운영자 지시 「카페 운영시간표를 반영할 수 있는 관리자 페이지 하나 신설 — 일정 반영이라고 만들어서 그 안에 첫 번째 메뉴로 카페 운영 일정. 파일은 이런 식으로 첨부될 거임. OCR 있으니까 그거 활용하게 해도 될 듯(블로그 제작 기능에 OCR 있음)」
캡처는 전부 헤드리스 크로미엄 실측(?qa=admin 목데이터 = 실API·실데이터·PII 미접촉). 대상 = index.html.

1. 들어가는 문 — 관리자 패널 (전 / 후)

기존 관리 6종 뒤에 「일정 반영」 한 장이 붙는다. 카드 골격·여백·호버색 전부 기존 그대로 — 신규 형태 0. 톱니(관리) 드롭다운도 같은 순서로 항목이 하나 늘었다(구분선 위 데이터 관리 묶음의 마지막).

톱니 드롭다운 실측 — 전: 로그 조회·플랫폼·사용자·프로그램·신청 일정·불편사항 / 후: 그 뒤에 일정 반영. 구분선 아래 시스템 설정(자동 잠금 시간·예울이 페르소나)은 자리 그대로.

2. 일정 반영 — 메뉴 페이지

「그 안에 첫 번째 메뉴」 = 카페 운영 일정. 다음 일정표(장도 입도 시간 등)가 생기면 _CS_MENU 배열에 한 줄만 늘리면 된다.

3. 카페 운영 일정 — 이미지 한 장에서 시트까지

흐름

  • OCR = 기존 것을 그대로 쓴다 — 블로그 도우미가 쓰는 POST /api/content/ocr. Worker 신설 0·시크릿 신설 0.
  • 표 읽기 = 「N월 N일」 앵커 분할. OCR 엔진마다 표를 줄 단위로 주기도(제미나이 비전) 셀 단위로 주기도(비전 API) 하는데, 둘 다 읽기 순서 = 표 열 순서(일자·요일·열어요·닫아요·비고·운영시간)라 날짜로 구간을 자르고 앞 두 시각만 쓰면 형태와 무관하게 같은 결과가 나온다. 실측 = 두 형태 입력이 31일 전건 동일.
  • 비고의 시각에 안 섞인다 — 8/22 「[소]메타타악앙상블 17:00」은 닫아요 뒤 열이라 앞 두 개(11:00·17:30)에 안 들어온다. 반대로 합계 「N시간 M분」은 맨 뒤 열이라 마지막 것을 쓴다 — 8/29 비고의 「인터미션 15분」에 안 걸리게.
  • 시트는 [날짜, 운영시간] 2열 그대로. 비고(대관)는 시트에 없는 열이라 화면 확인용으로만 보여주고 쓰지 않는다 (docs/260703_cafe_july_ingest.mjs가 7월분에서 내린 판단과 같은 축 — 열 추가는 운영자 결정 사항).

5. 쓰기 — 무엇을 건드리고 무엇을 안 건드리나

  • 신규만 있으면 POST /api/ops {mode:'append'} — 7월분 스크립트와 같은 경로. 기존 행 물리적 무접촉.
  • 값이 바뀐 날짜가 섞이면 전체 교체. 단 읽어온 원본 행을 그대로 들고 가서 해당 날짜의 운영시간만 갈아끼운다.
  • 시트를 못 읽었으면 반영 버튼 자체가 꺼진다 — 신규/변경 판정 없이 전체 교체가 나가는 사고를 원천 차단.
  • 쓰기 뒤 재조회로 확인하고, 확인되지 않으면 「반영은 보냈는데 아직 안 보인다」고 그대로 말한다(성공했다고 하지 않는다).

  • 신규 색 0 · raw hex 0 — check_design 1590/1590 유지. 상태색은 기존 역할칩 그대로(신규 --accent 틴트 · 변경 --peach-text 틴트 · 동일 --neutral · 경고 --danger-btn). 경고 행 배경은 --danger-btn alpha 변주(§3.5② · .btn--danger 그림자와 같은 성분).
