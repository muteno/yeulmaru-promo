### 🔴 [보안-1] `src/index.js` `/api/hwp/upload` — 업로드한 .hwp 원본이 **공개 git 이력에 영구 잔존**

### 🔴 [보안-2] Pages 정적 서빙 — `drafts/` 경로가 **무인증 직접 다운로드** 가능
- Worker의 `roleOf` 인증 게이트는 **API만** 보호한다. `promo.yeulmaru.org/drafts/hwp/<id>.in|out.hwp` 는 Pages 정적 경로라 인증이 걸리지 않는다. `sw.js`의 `NEVER` 목록은 **SW 캐시 제외**일 뿐 서빙을 막지 않는다.
- 최소 수정: `drafts/`를 Pages 서빙 대상에서 제외(별도 브랜치) 하거나 리포 비공개화.

### 🟠 [보안-3] `.github/workflows/hwp-edit.yml` — 프롬프트 인젝션 → 허용된 `Bash` → 러너 env(활성 OAuth 토큰) 유출 경로
- `--allowedTools 'Bash,Read,Write,Edit,Glob,Grep,Skill'` 에 Bash가 포함되고 러너는 외부 네트워크가 열려 있다. 프롬프트의 "외부 전송 금지"는 **지시일 뿐 강제가 아니다**. `claude_failover.js`가 `process.env` 전체를 자식에 상속시킨다.
- **셸 인젝션은 아님**(execFileSync 배열 인자 + stdin 주입 = YAML/셸 이스케이프는 안전). 형제 계정 토큰은 failover가 제거하므로 유출 반경은 **활성 토큰 1개 + 러너 env**로 한정.
- 실제 도달성 = **중간**(인증 사용자만 dispatch 가능 + Claude 자체 거부). 방어심층 공백에 해당.
- 최소 수정: 자식 프로세스에 `process.env` 통째 상속 금지(최소 env 화이트리스트).

### 🐛 [버그-5] `.github/workflows/hwp-edit.yml` — hwp 산출물 자동정리가 **id 산술 오류로 영원히 실행되지 않는다**
- hwp id = `'hw' + Date.now() + Math.floor(random*1000)` 로 **구분자 없이 연결** → 16자리. 청소 코드는 `f.match(/^hw(\d+)\./)` 로 16자리를 통째로 캡처한 뒤 13자리 `Date.now()`와 빼기 → 결과가 항상 **음수**(실측 시뮬레이션 `-1.78e15`) → `> ttl` 조건이 **영원히 false**.
- 대조군: 채팅 id는 `'yc'+Date.now()+'r'+rand` 로 **`r` 구분자**가 있어 `^yc(\d+)r` 가 13자리만 캡처 = 정상 동작. hwp만 이 구분자가 빠졌다.
- 영향: 「원본 1시간·수정본 3일 뒤 자동 정리」 주장이 **무효**. `.out` 수정본과 상태 json이 공개 브랜치 tip에 **영구 누적**된다(= 보안-1·2의 노출 창을 상시 열어둔다).
- 최소 수정: 청소 정규식을 `/^hw(\d{13})/` 로 바꾸거나, id 생성을 `'hw'+Date.now()+'r'+rand` 로 구분자 삽입.
