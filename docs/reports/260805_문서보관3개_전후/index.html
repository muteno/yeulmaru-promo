이 레포는 공개 레포다. raw.githubusercontent.com에 비인증 GET → HTTP 200 실측. 즉 drafts/에 남은 파일은 누구나 받을 수 있다 — 남겨 두는 개수가 곧 노출 면적이다.

2. 고친 방식 — 시간(TTL)이 아니라 개수

공용 회수기 shared/drafts_retain.mjs 신설. 네 워크플로(nb-blog·hwp-edit·office-edit·slim)가 커밋 직전에 호출한다. 정기 크론은 안 만들었다 — 이 레포는 정기 봇 커밋 축이 없고(CLAUDE.md 「빌드 큐」 절), 신설하면 그 절의 짝 규칙이 따라붙는다.

  • 시각은 정렬에만 쓰고 임계 비교를 안 한다 → 위 ②의 16자리 함정을 원천적으로 안 밟는다(그래도 \d{13}로 못박음).
  • 접두(nb·yc·hw·of·sl)별로 최근 3개. 이번 런 id는 개수와 무관하게 보호.
  • 원본(.in)은 이번 런 것만 남긴다 — 결과가 나온 뒤엔 쓸모가 없고, 남의 문서 노출만 늘린다.
  • 규약 밖 파일은 손대지 않는다(사람이 둔 파일 보호).

3. UI 반영 — 「서버에 얼마나 남는지」를 올리기 전에 알린다

왜 「최근 문서 목록」을 안 만들었나. 목록으로 띄우면 공개 레포라 남의 공문·예산안이 서로 보이게 되고, 이 레포의 🔒 공용 PC 원칙(닫으면 상태 전멸)과 정면으로 충돌한다. 대신 보관 정책을 문구로 알린다 — 문구는 상수 _DRAFT_NOTE 하나를 세 모달이 공유하고, _DRAFT_KEEP은 회수기의 keep과 같은 값이다.

디자인 = 기존 .u-empty 안내 문구 자리에 한 줄 추가. 신규 CSS 0 · 신규 raw hex 0(check_design index 1578 무변) · 신규 컴포넌트 0.
