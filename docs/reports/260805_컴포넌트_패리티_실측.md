# 정본 컴포넌트 패리티 실측 — 260805-24

> 산출 = `tools/smoke_component_parity.mjs` 헤드리스 실측(1500×1000 · `?qa=admin` · 기본 화면 + 모달 35개).
> 기준값은 이 문서에도, 스모크에도 **안 적는다** — 정본은 CSS 하나뿐이고 실측은 「서로 같은가」만 묻는다.

## 왜 쟀나

260805-23 모달 머리줄 작업에서 **소스 게이트는 전건 PASS인데 화면엔 소스가 글자로 찍힌** 사고가 났다
(`\'+_mhead(...)+\'` = 이스케이프된 따옴표). 「소스에 있다」와 「그려졌다」는 다른 축이고, 그걸 잡은 건
브라우저 실측 스모크였다. 그 방법을 기틀 §2 정본 컴포넌트 전체로 넓힌 것이 이번 실측이다.

계약 한 줄: **「클래스가 같으면 픽셀도 같아야 한다」.** 같은 정본 컴포넌트가 자리마다 다르게 그려진다면
누군가 그 자리에서 손으로 다시 튜닝한 것이다.

## 잠금 방식 — 래칫

`tools/smoke_component_parity.mjs` + `tools/component_parity_baseline.json`(**기계산출물 · 손편집 금지**).
판정은 check_design ①~⑥과 같은 **「지금보다 나빠지지만 마라」**:

- 어떤 컴포넌트의 갈래가 baseline보다 **늘면 FAIL**
- baseline에 없는 컴포넌트가 **처음부터 갈려 있어도 FAIL**
- 줄면 PASS + 「baseline 하향 갱신 권장」 안내

승인분 반영 = `node tools/smoke_component_parity.mjs --update`.

**킬테스트 실증(260805-24)**
- 기존 컴포넌트 한 자리를 인라인 재튜닝(프로그램 필터 「적용」에 `padding:14px 30px`) → `.m-btn.save 2 → 3가지` **rc=1**
- 새 컴포넌트가 처음부터 갈림(`.toast` 하나만 `border-radius:2px`) → `신규 드리프트` **rc=1**
- 원복 → **rc=0** · 연속 3회 실행 결과 동일(흔들림 0)

### 설계 판단 하나 — 부모 문맥을 키에 안 넣는다

처음엔 키를 `(부모 정본 클래스) > (자기 클래스)`로 잡았다. 그러면 `.mhead .sub`가 맨 `.sub`과 안 섞여
깔끔해 보이는데, **킬테스트에서 드리프트를 통째로 놓쳤다**: 프로그램 필터의 「적용」은 부모가 `.modal-acts`라
`modal-acts > m-btn.save`라는 자기만의 키가 되고, 그 키의 유일한 인스턴스라 아무리 튜닝해도 갈래가 1로 남는다.
→ 문맥을 빼고 `.sub` 과적재는 findings(#2)로 남기는 쪽을 골랐다. **놓치는 것보다 낫다.**

## 260805-36 확정 — 운영자 선택 「전 축 정본(최다)」 → 갈래 7 → **1**

운영자가 시안에서 7축 전부 **정본(최다)** 를 선택. 적용 내역:

| 축 | 걷어낸 것 | 결과 |
|---|---|---|
| `.m-btn.cancel` · `.save` | `.pw-acts .m-btn{padding:9px 22px}` 규칙 삭제 | 위아래 10px 하나 |
| `.nb-chip` · `.on` | `#ve-board .nb-chip{padding:10px 11px;border-radius:4px}` 규칙 삭제 | 알약 999px · 5·11 하나(영상 편집기 비율 칩도 알약) |
| `.nb-input` | 인라인 `font-size:12.5px` + `padding:8px 11px`·`7px 8px` 6곳 제거 | 13px · 10·14 하나 |
| `.u-empty` | 인라인 `padding:` 16곳 + 중복 `text-align:center` 제거 · 정본에 `font-size:16px` 명시 | 44·24 · 16px 하나 |
| `.sub` | `.bizm-hero .lb .sub` 500 · `.bizm-card .ct .sub` 400 → **600**(최다) | 회색 쪽 굵기 1갈래 |

### 남은 1갈래 = `.sub` 이름 충돌 — **합치지 않는 것이 정답**

`.mhead .sub`(머리줄 부제 · 흰 `rgba(255,255,255,.85)` 11.5px)와 범용 `.sub`(회색 `#888` 11px)는 **뜻이 다른 두 컴포넌트가 같은 클래스명을 쓰는 것**이다. 「정본(최다)」를 글자 그대로 적용하면 **294곳의 회색 보조문구가 흰 글자가 되어 흰 배경에서 사라진다**. 그래서 이 축만 선택을 문자 그대로 적용하지 않았다 — 시안에도 「통일이 아니라 이름을 나누는 게 답」으로 적어 둔 축이고, 실제로 한 일은 **회색 쪽 내부의 굵기 3갈래를 1로 줄인 것**이다.

- 남은 해소 방법 = 범용 쪽 클래스명을 바꾸는 **리네이밍**(예: `.sub` → `.hint`) — 앱 전역 294곳 + 스코프 규칙 4개를 함께 옮기는 작업이라 별건으로 남긴다.

### 시안 렌더 버그(운영자 지적) — 실물은 정상

운영자 「선택칩 버튼이 픽셀 단위로 보면 좀 무너져 있다」. **실물 확인 = 정상**(`.nb-chip.on` 6배 확대 실측 = 네 변 1px `rgb(74,77,231)` · radius 999px · padding 5·11). 원인은 **시안 생성기**였다 — 패리티 서명에 `borderTopWidth`/`borderTopColor`만 있는데 `border-style:solid`를 네 변에 줘서 좌·우가 폭 기본값(medium=3px)·색 `currentColor`로 그려졌다. 윗변 값을 네 변에 펴 주도록 고치고 기록본을 다시 생성했다.
