## 2. 진단 — 구판(칩)의 문제 2건

1. **의미가 틀렸다.** 기간은 상호배타인데 `.ana-chip`(칩)을 썼다. 규범상 칩은 「여러 개 고를 수 있다」를 뜻해서, 화면이 「3일과 7일을 같이 켤 수 있나?」로 읽힌다. 이 레포엔 이미 **상호배타 전용 정본 `.fbar-seg`**(기틀 §2 · 「세그먼트(상호배타) — 상태탭·회차·진행일」)와 빌더 `_chipRow`가 있었다 — 즉 **정본을 안 쓰고 다른 부품을 끌어다 쓴 것**이 실수.
2. **라벨을 인라인으로 다시 타이핑했다.** 「기간」 글자를 정본 `.fbar-lbl` 대신 인라인으로 적으면서 색이 `--dim`으로 어긋났다(정본 = `--neutral-text`). 260805-24 계약(「클래스가 같으면 픽셀도 같아야 한다」)이 경고하는 바로 그 드리프트.

## 3. 적용 — 정본 복귀 + 접근성 보강

- **부품 교체**: `.ana-chip` 4개 → **`.fbar-seg` 세그먼트 한 벌**(`_chipRow` 빌더 재사용 = 회차·진행일과 같은 한 벌). 선택 칸이 강조색으로 **꽉 차서** 「하나만 고른다」가 한눈에 읽힌다(구판 = 옅은 테두리 = 토글로 읽힘). 칸 수 4 = 권장 2~5 안.
- **라벨**: 인라인 재타이핑 삭제 → 정본 `.fbar-lbl`(색 어긋남 해소).
- **접근성(빌더에 넣어 앱 전체가 함께 좋아진다)**: `role="group"` + `aria-label` · 선택 칸에 **`aria-current="true"`**. 구판은 선택 상태가 **색으로만** 있어 스크린리더에 안 들렸다 = 결손이었다. Primer 명문대로 `radiogroup`/`tablist`/`toolbar`는 **주지 않는다**. 시각 변화 0(속성만 추가).
- **빌더 확장**: `_chipRow(label, opts, cur, fn)`의 `opts`가 `{v:값, t:라벨}`도 받게 했다(값≠라벨 — 기간은 값이 숫자 3·7·30·0, 라벨은 「3일 이내 3」). 문자열을 주면 종전과 동일 = 기존 호출처(회차·진행일) 무회귀.
- **건수 유지**: 칸마다 건수를 붙인 건 대시보드 규범 「빈 결과로 들어가게 하지 마라」 — 0이면 누르기 전에 보인다. *비활성(disabled) 상태로 막는 방법은 이 레포에 선례가 없어 만들지 않았다*(기틀 규칙 3 — 없는 형태는 창작 금지).

## 5. 안 바꾼 것과 이유

- **세그먼트의 생김새 자체**(칸 사이 간격이 있는 형태). M3 최신판은 「connected button group」(칸이 붙은 형태)을 권하지만, 그건 **새 형태 도입** = 기틀 규칙 2·3 위반이라 세션이 임의로 못 정한다. 필요하면 운영자 판단 사항.
- **라벨 문구**(「3일 이내」). 규범은 짧은 라벨을 권하지만 운영자가 쓴 말이 그대로 화면에 있는 편이 낫다고 봤다. 모바일에서도 넘침 0으로 확인됐다.
