1. 무엇이 문제였나 — 「아직 안 왔다」와 「진짜 0건」을 구분하지 않았다

두 반쪽의 소스는 서로 다르고 도착 시각도 다르다. 교육 반쪽은 도착 여부를 아예 묻지 않아, 안 온 상태를 없는 상태로 단정했다.

반쪽소스전 — 미도착일 때 화면후
기획 전시_anaState._exMaster

왜 사람 눈에 「오류」로 읽혔나 — 📭 + 「등록되면 …에 표시됩니다」는 운영자가 시트에 뭘 안 넣었다는 뜻의 문장이다. 데이터가 오는 중일 뿐인데 화면이 「네가 등록을 안 했다」라고 말하고 있었다.

2. 전후 — 교육 반쪽 (부팅 후 ≈2.0초 · 1920×1080)

같은 타임라인 지점에서 잡은 두 컷. 전시는 이미 도착해 그려졌고, 교육(PERFS)은 아직 오는 중인 순간이다. 재현 조건 = 프로그램 시트 3.2s / 운영대장·전시 2시트 0.9s (프로그램 시트가 가장 큰 시트라 실제로 늦게 오는 순서).

후 (after) — 「교육 데이터 불러오는 중」(.sk-sweep 빔 + 점 픽토그램)

3. 전후 — 전시 반쪽이 못 받아온 경우

전시 원천 2시트가 실패하는 조건(각 fetch가 .catch → null). 구판은 실패해도 _bizExhibEnsure가 조용히 빠져나가 로더가 그대로 남았다 — 코드 주석엔 「불러오지 못했어요로 남는다」라고 적혀 있었지만 그 상태가 실제로는 없었다.

전 (before) — 추적 7초 내내 스윕만 도는 무한 로딩
후 (after) — 실패 카드 + 「다시 시도」(정본 실패 문법 계승)
⚠ 무한 fetch 고리 방어 — 실패 → 재렌더 → 재확보 → 실패 …가 되지 않게, 실패 딱지(window._bizmExFail)가 서 있으면 자동 재확보를 멈춘다. 재확보는 「다시 시도」를 누를 때만. 실측 호출 수 = 전시마스터·전시일일 각 2회(레일 6시트 1 + 반쪽 자체 확보 1)로 유한.
