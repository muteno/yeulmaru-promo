1. 투데이스 브리핑 — 로그인 후 자동 팝업 소거

끈 것은 자동 팝업 한 자리(initApp의 _paTodayPop() 호출)뿐이다. 브리핑 본체·「AI 홍보」 메뉴 경로·크론은 손대지 않았다.

전 — 로그인 1.5초 뒤 우하단에 뜸
후 — 같은 조건에서 안 뜸

실측: 브리핑 API 2종(/api/promo/auto-latest·/api/blog/draft)을 가짜 응답으로 채워 팝업이 뜨는 조건을 갖춘 상태에서 부팅 — 전 {shown:true} · 후 {shown:false}(4.5초 대기).

지운 게 아니라 잠근 것. _paTodayPop·_paTodayOff·#pa-today는 그대로 살아 있다. 롤백 = 주석 1줄 해제.

2. 캘린더 빗금 칸 — 빗금만 옅게, 날짜 글자는 원래 잉크

빗금(.diag = 45° 대각선 α.02)이 쳐지는 칸 = 다음 달 날짜 칸(.c.nm). 구판은 빗금뿐 아니라 날짜 글자까지 rgba(0,0,0,0.1)로 지워 숫자가 안 읽혔다.

전 — 글자 rgba(0,0,0,0.1) (1·2·3·4·5·6이 거의 안 보임)
후 — 글자 var(--text) = rgb(26,26,46) · 빗금은 그대로

5. 함께 좁힌 검증 2곳 (완료 건에만)

완료 건의 내용 수정이 다른 규칙에 걸려 조용히 막히는 자리를 두 곳 열었다. 예정·신청 중 건의 판정은 무변이다.

  • 홍보 기간 창 검사 — 완료 건은 이미 나간 홍보라 창 판정 대상에서 제외(_perf=null). 안 그러면 「홍보 종료 후라 홍보할 수 없어요」가 오탈자 수정까지 막는다.
  • 카카오/문자 충돌 검사 — 완료 건은 플랫폼 값이 실제로 바뀐 경우에만 검사. 값이 그대로면 인접일 건의 「연일 회피」에 걸려 과거 실적의 문구 수정이 막힌다.
완료 건에서 일자·시간·프로그램은 저장 단계에서도 한 번 더 거부한다(UI 자물쇠 + 서버 직전 가드 2중).

각주 — 3번 화면은 실제 시트 대신 목 레코드(신청자 「홍길동」)를 주입해 재현했다. 브리핑 팝업은 QA 모드에 실데이터가 없어 API 2종을 가짜 응답으로 채워 「뜨는 조건」만 만들었다 — 팝업 마크업·위치는 정본 그대로다.
