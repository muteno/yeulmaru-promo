3. 어떻게 만들었나 (배선 요약)

높이를 애니메이션하지 않는다. 카드를 처음부터 열 전체 높이로 깔고(.cb-rise{position:absolute;inset:0}) 평소엔 아래 --rise-h만큼만 clip-path:inset(…)로 보여준다. 펼침 = 그 잘라내기가 0으로 가는 것뿐 — 리플로 0·합성만이라 check_design.py ⑥ 잰크 전이가 15/15 그대로(높이·마진 전이였으면 16이 되어 커밋이 막힌다).
입력줄은 한 픽셀도 안 움직인다 — 카드가 바닥에 고정돼 있고 위쪽 선만 올라가니, 타이핑 중에 열려도 커서가 안 흔들린다.
자리 확보 = 열의 padding-bottom:calc(var(--rise-h) + var(--rise-gap)). 그래서 위 막대 카드 높이는 전과 Δ0(실측 414px).
접힘 칸 --rise-h = 로그창 clamp(96px,16vh,190px) + 입력줄·테두리 --rise-foot(_memAiPaint가 .cb-foot 실측으로 덮어씀 · 실측 61+2=63) = 1500×1000에서 223px = 이 기능 배선 전과 같은 값.
쉼 상태는 손대지 않는다(260813-4 · 운영자 「위에 이미 있는 내용의 간격들은 그대로 유지」) — 260813-2의 접힘 칸 304px은 되돌렸다. 접힘 칸은 열의 padding-bottom으로 자리를 예약하는 값이라 키운 만큼 위 막대 카드가 실제로 줄어든다(1500×1000 414 → 333 · 1920×1080 474.8 → 406.6). 넓어지는 건 켜져 있는 동안 덮는 것뿐 — 카드가 절대배치·불투명이라 위 카드를 밀지 않고 덮는다. 260813-3의 차트 우선 상한(--rise-avail·_memRiseFit·ResizeObserver)은 304를 되돌리려던 보정이라 함께 걷어냈다(어느 창에서도 하한 159px에 먼저 걸려 발동하지 않는다).
실측 = 막대 카드 1500×1000 414.0 · 1920×1080 474.8 · 1366×768 237.7 — 세 창 전부 배선 전과 Δ0. 접힘 칸 223 / 235.8 / 185.9.
진입로 2개 — :hover(마우스)와 :focus-within(터치·키보드로 입력칸에 들어갈 때). 감속 선호(prefers-reduced-motion)면 전이 없이 즉시 전환.
대화는 아래에 붙는다(.cb-rise>.cb-body>:first-child{margin-top:auto}) — 로그창이 늘 열 전체 높이라 위로 붙이면 접힘 칸이 빈 칸이 된다.
