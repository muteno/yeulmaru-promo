### ✅ git (풀패스 + Start-Process + 파일 리다이렉트)
```powershell
$git="C:\Program Files\Git\bin\git.exe"
$repo="C:\Users\$env:USERNAME\OneDrive - GS칼텍스 예울마루\DAX\Sewoong Hwang\yeulmaru-promo"
$o="$env:TEMP\g_o.txt"; $e="$env:TEMP\g_e.txt"
function G([string[]]$x){ Start-Process -FilePath $git -ArgumentList $x -WorkingDirectory $repo -NoNewWindow -Wait -RedirectStandardOutput $o -RedirectStandardError $e; $oc=Get-Content $o -Raw -EA SilentlyContinue; $er=Get-Content $e -Raw -EA SilentlyContinue; if($oc){Write-Output $oc}; if($er){Write-Output ("[err] "+$er)} }
G @('fetch','origin'); G @('status','--short','-b'); G @('log','--oneline','-3')
```
- push 진행상황·`LF will be replaced by CRLF` 경고는 `[err]`(stderr)로 나와도 정상. 한글 commit은 ASCII 파일에 저장 후 `-F`:
```powershell
Set-Content "$env:TEMP\cmsg.txt" -Value "fix: ..." -Encoding ASCII -NoNewline
G @('-c','user.name=yeulmaru','-c','user.email=yeulmarulicense@gmail.com','commit','-F',"$env:TEMP\cmsg.txt")
G @('push','origin','main')
```

## 🏗️ 시스템 설계 — 데이터가 어떻게 흐르는가

```
[브라우저] index.html (Vanilla JS 단일파일 ~7,100줄, GitHub Pages)
    │  fetch (X-App-Password / X-Sub-Admin-PIN 헤더)
    ▼
[Cloudflare Worker] src/index.js  (프록시 + 인증 + cron)
    │  Microsoft Graph API (Azure AD service account 토큰)
    ▼
[SharePoint Excel] "통합 문서1.xlsm" = 데이터 마스터 (시트별 slug 매핑)
```

### 🚨 두 갈래 흐름 — 섞으면 데이터 손상 (필독)
| 무엇을 바꾸나 | 어디서 | 경로 | 속도 |
|---|---|---|---|
| **시트 데이터**(PIN/홍보기록/일정/설정) | **모달에서만** | Worker→Graph→SharePoint 마스터 | 1~3초 |
| index.html / CSS / JS | 에디터+git push | GitHub→Pages | 1~2분 |
| Worker 코드 | Cloudflare Quick Edit/wrangler | (git 무관) | 즉시 |
| CLAUDE.md / docs | 에디터+git push | GitHub (동작영향 X) | - |

- **모달 데이터 변경은 OneDrive를 안 거친다.** Worker가 Graph API로 마스터 xlsm을 직접 수정. OneDrive sync는 로컬 복사본을 뒤늦게 따라오게 할 뿐.
- 🚫 **로컬 `통합 문서1.xlsm` 직접 편집 절대 금지.** OneDrive가 SharePoint에 push 시도 → Worker 수정과 충돌 → conflict copy + 손상. `.gitignore`로 `*.xlsm` 차단됨. **데이터 구조 참고용 read-only로만** 열 것.

  - ② **포맷 전환은 OOXML 에서만.** 투명 픽셀이 있으면 PNG 유지(로고 배경 보존 — 실측 900×900 중 405,000px 투명 보존), 없으면 JPEG 전환. 전환하면 파트 이름·`.rels` Target·`[Content_Types].xml` 선언을 **따라서 고친다**(안 고치면 엑셀이 「복구할 수 없는 내용」이라며 거절). **hwpx·hwp는 매니페스트(「Contents/content.hpf」)·DocInfo 형식 문자열이 얽혀 있어 전환 금지** — 같은 포맷 축소만.
  - 캔버스가 못 여는 형식(EMF/WMF 벡터 등)은 무접촉 — 지우면 도형이 사라진다.
- **⚠ PDF에 `-dPDFSETTINGS=/ebook` 프리셋을 쓰지 마라(260805 실측)** — **사진을 안 줄인다.** gs는 `PassThroughJPEGImages`가 기본 참이라 JPEG를 무손질 통과시키고 프리셋의 DownsampleThreshold(1.5)까지 겹쳐, 290dpi 사진이 `/ebook`·`/printer`에서 **그대로 나왔다**(1.24MB → 1.24MB · 오히려 +2KB). `slim_runner.mjs`처럼 다운샘플 파라미터를 직접 지정해야 실제로 준다(같은 파일 → 152KB/398KB). **글자는 글자로 남는다** — 페이지를 사진으로 굽지 않으므로 본문 검색·복사가 살아 있다(실측 = 추출 글자수 284,591 → 284,958 보존).
- **구형 `.hwp` = CFB 컨테이너의 `BinData/` 스트림만 교체**(SheetJS `cfb` · 왕복 바이트 동일 실측). BinData의 압축 여부는 파일 헤더 플래그만으론 못 정한다(DocInfo `HWPTAG_BIN_DATA`가 항목별로 따로 갖는다) → **풀어보고 되는 쪽을 쓰고 원래 상태로 되돌린다**. 실측 4.85MB → 0.24/0.51/1.30MB · 사진 외 스트림 변조 0 · 유실 0.
- **경로**: 앱 `_slRun()` → (ZIP 계열은 여기서 끝) / (PDF·hwp) Worker `/api/slim/upload`(`drafts/slim/<id>.in.<ext>` 커밋) → `/api/slim/dispatch`(`repository_dispatch: slim` — 전용 event_type이라 블로그·한글·오피스 큐에 안 막힌다) → `slim.yml` → `drafts/slim/<id>.out.<ext>` + `drafts/<id>.json` → 앱이 공용 `/api/blog/draft?id=`로 폴링 → `/api/slim/file`로 바이트 수령 → 자동 내려받기.
- **데이터 위생**: 브라우저 갈래는 **애초에 아무 데도 안 올라간다**. 러너 갈래만 원본을 워크플로 끝에 즉시 삭제 + 잔재 자동 회수(원본 1시간/결과 3일). 앱은 닫으면 상태 전멸(공용 PC). **시크릿 신설 0**(`GITHUB_PAT`만 · OAuth 불요).

| 진입점 | 어디 | 마무리 | 코드 |
|---|---|---|---|
| **홍보 신청 위저드** [AI 문구 제안] | 카카오톡 본문 step(76자 칸) 라벨 바 | 입력칸에 **넣기** | `_pwAiRun`~`_pwAiPick` · `#pw-ai-box` |

- **톤 칩 + 덧붙일 말 → 서버의 `담당자 요청` 한 줄**(`_kmAsk`) — 엔드포인트 계약 그대로라 **서버 프롬프트를 안 건드린다**.
- ⚠ **`.btn`엔 `:disabled` 규약이 없다** — 비활성이 활성처럼 보이므로 인라인 `opacity:.45`로 흐린다(신규 CSS 0). busy는 정본 `_btnBusy`(기틀 §2 #13 · dots + `~중`).

- **Worker `POST /api/content/kakao`** = ①페이지 열기(`kkoFetchPage`) ②포스터·상세 이미지 OCR(`kkoOcrImages` → **기존** `runExternalOcr`) ③`llmText` 후보 생성. **시크릿 신설 0** — `GEMINI_API_KEY` 하나가 OCR·LLM 둘 다 한다.
- **⚠ 이미지 판별 = 「`<article>` 안 + `/inday_fileinfo/`」 (260805 실측 · 손대지 말 것)**: `og:image`는 **전 페이지 공통 기본값**이라 포스터가 **아니고**(`og:title`도 「예울마루」 고정), `/src/img/`는 로고·스와이프 등 사이트 크롬, 헤더 네비의 대관 썸네일은 `/inday_fileinfo/`지만 `<article>` 밖이다. **두 조건을 함께** 걸어야 포스터+상세페이지 2장만 남는다(공연·전시 두 페이지형 실측). 0장이면 본문 이미지 → og:image 순 폴백, 그래도 없으면 페이지 텍스트만으로 진행한다.
- **⚠ 페이지 텍스트 + OCR 둘 다 쓴다**: HTML엔 일시·장소·티켓가격·할인정보가 표로 있지만 **출연자·프로그램·홍보 카피는 이미지 안에만** 있다(실측). 사실은 텍스트에서, 표현은 OCR에서 나온다 — 한쪽만 쓰면 문구가 비거나 틀린다.
