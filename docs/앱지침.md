### ✅ git (풀패스 + Start-Process + 파일 리다이렉트)
```powershell
$git="C:\Program Files\Git\bin\git.exe"
$repo="C:\Users\$env:USERNAME\OneDrive - GS칼텍스 예울마루\DAX\Sewoong Hwang\yeulmaru-promo"
$o="$env:TEMP\g_o.txt"; $e="$env:TEMP\g_e.txt"
function G([string[]]$x){ Start-Process -FilePath $git -ArgumentList $x -WorkingDirectory $repo -NoNewWindow -Wait -RedirectStandardOutput $o -RedirectStandardError $e; $oc=Get-Content $o -Raw -EA SilentlyContinue; $er=Get-Content $e -Raw -EA SilentlyContinue; if($oc){Write-Output $oc}; if($er){Write-Output ("[err] "+$er)} }
G @('fetch','origin'); G @('status','--short','-b'); G @('log','--oneline','-3')
```
- push 진행상황·`LF will be replaced by CRLF` 경고는 `[err]`(stderr)로 나와도 정상. 한글 commit은 ASCII 파일에 저장 후 `-F`:
```powershell
Set-Content "$env:TEMP\cmsg.txt" -Value "fix: ..." -Encoding ASCII -NoNewline
G @('-c','user.name=yeulmaru','-c','user.email=yeulmarulicense@gmail.com','commit','-F',"$env:TEMP\cmsg.txt")
G @('push','origin','main')
```

## 🏗️ 시스템 설계 — 데이터가 어떻게 흐르는가

```
[브라우저] index.html (Vanilla JS 단일파일 ~7,100줄, GitHub Pages)
    │  fetch (X-App-Password / X-Sub-Admin-PIN 헤더)
    ▼
[Cloudflare Worker] src/index.js  (프록시 + 인증 + cron)
    │  Microsoft Graph API (Azure AD service account 토큰)
    ▼
[SharePoint Excel] "통합 문서1.xlsm" = 데이터 마스터 (시트별 slug 매핑)
```

### 🚨 두 갈래 흐름 — 섞으면 데이터 손상 (필독)
| 무엇을 바꾸나 | 어디서 | 경로 | 속도 |
|---|---|---|---|
| **시트 데이터**(PIN/홍보기록/일정/설정) | **모달에서만** | Worker→Graph→SharePoint 마스터 | 1~3초 |
| index.html / CSS / JS | 에디터+git push | GitHub→Pages | 1~2분 |
| Worker 코드 | Cloudflare Quick Edit/wrangler | (git 무관) | 즉시 |
| CLAUDE.md / docs | 에디터+git push | GitHub (동작영향 X) | - |

- **모달 데이터 변경은 OneDrive를 안 거친다.** Worker가 Graph API로 마스터 xlsm을 직접 수정. OneDrive sync는 로컬 복사본을 뒤늦게 따라오게 할 뿐.
- 🚫 **로컬 `통합 문서1.xlsm` 직접 편집 절대 금지.** OneDrive가 SharePoint에 push 시도 → Worker 수정과 충돌 → conflict copy + 손상. `.gitignore`로 `*.xlsm` 차단됨. **데이터 구조 참고용 read-only로만** 열 것.

- **왜 폴링을 새로 안 만들었나**: `drafts/<id>.json` 규약이 이미 블로그·예울이 채팅과 공용이라 그대로 태웠다(엔드포인트 신설 0). 결과 파일만 별도 경로 = JSON에 base64로 넣으면 contents API 1MB 상한에 걸리기 때문.
- **왜 플러그인 설치가 아니라 스킬 복사인가**: 헤드리스에서 마켓플레이스 신뢰 프롬프트에 걸릴 여지를 없애고, 업스트림 버전을 워크플로 `CLAW_HWP_REF`로 고정하려는 것. 업스트림이 깨지면 그 값을 태그로 내리면 된다.
- **데이터 위생**: 원본은 워크플로 끝에 즉시 삭제 · 잔재는 원본 1시간/수정본 3일 뒤 자동 회수 · 앱은 닫으면 상태 전멸(공용 PC) · 업로드 상한 8MB.
- **시크릿은 신설 0** — 블로그 초안이 쓰는 `GITHUB_PAT`(Worker)·`CLAUDE_CODE_OAUTH_TOKEN_*`(Actions) 그대로. 블로그 초안이 되면 이것도 된다.

## 🗓 관리 ▸ 일정 반영 (260804) — 받은 일정표를 앱 데이터로

### 카페 운영 일정 (`openCafeSchedule` · `cs-*`)
「카페 공감 N월 운영시간」 표 이미지 → **기존 OCR**(`POST /api/content/ocr` · 블로그 도우미와 같은 경로, **Worker·시크릿 신설 0**) → 하루 한 줄로 정리 → 사람이 확인·수정 → `운영_카페일정` 시트 반영.

- **표 읽기 = 「N월 N일」 앵커 분할.** OCR 엔진마다 표를 줄 단위로 주기도(제미나이 비전) 셀 단위로 주기도(비전 API) 하지만 **읽기 순서 = 표 열 순서**(일자·요일·열어요·닫아요·비고·운영시간)라, 날짜로 구간을 자르고 그 안 **앞 두 시각**만 열어요·닫아요로 쓰면 형태와 무관하게 같은 결과가 난다. 비고에도 시각이 있지만(「[소]메타타악앙상블 17:00」) 닫아요 **뒤** 열이라 안 섞인다. 합계 「N시간 M분」은 맨 뒤 열이라 **마지막 것**을 쓴다(비고의 「인터미션 15분」 회피).
- **자기검증 = `docs/260703_cafe_july_ingest.mjs`(7월분 스크립트)의 요일 대조를 화면으로 옮긴 것.** ⚠ **표엔 연도가 없다** — 연·월 선택이 연도를 준다. 요일이 어긋나면 **반영 자체를 막는다**(원 스크립트가 `process.exit(1)`로 중단하던 자리). 나머지 = 합계 대조·형식/순서·빠진 날짜·중복 날짜(경고).
- **시트 = [날짜, 운영시간] 2열 그대로.** 비고(대관)는 시트에 없는 열이라 **화면 확인용으로만** 쓴다 — 7월분 스크립트와 같은 판단(열 추가 = 운영자 결정 사항, 「열 추가는 맨 끝 append만」 철칙과 별개로 미결).
- **쓰기 = 신규만이면 `mode:'append'`, 값이 바뀐 날짜가 섞이면 전체 교체**(읽어온 원본 행을 들고 가서 그 날짜의 운영시간만 갈아끼움 = 다른 열·행 무접촉). **시트를 못 읽었으면 반영 버튼이 꺼진다** — 대조 없는 전체 교체 차단. 쓰기 뒤 재조회로 확인하고, 확인 안 되면 「보냈는데 아직 안 보인다」고 말한다.
- 반영 값은 `_cafeHours`에도 즉시 반영 → 캘린더 날짜 패널 「카페 운영 시간」이 다음 열람부터 새 값.
- 🔒 공용 PC 원칙(블로그 도우미·한글문서 편집과 동일): 닫으면 상태 전멸.
- ⚠ **CSS 주석에 `.nb-*` 같은 별표 뒤 슬래시 금지** — 주석이 조기 종료돼 **바로 다음 규칙 한 줄이 통째로 삼켜진다**(260804 실측: `.cs-stage`가 죽어 모달 하단 버튼이 화면 밖으로). 게이트 4종이 전부 통과하므로 **헤드리스 실측 아니면 못 잡는다**.
