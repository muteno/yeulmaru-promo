# 유튜브 영상 저장이 막힐 때 — 쿠키 1회 설정 (운영자용)

## 무슨 일이 있었나 (260803 실측)

링크 자료수집에서 유튜브 [저장]을 누르면 변환이 실패한다. 화면에 뜨던
「초대형(6GB 초과) 여부를 확인해 주세요」는 **틀린 안내**였다(그 문구는 원인과 무관하게 항상 떴다).

진짜 원인은 이것이다:

```
ERROR: [youtube] Sign in to confirm you're not a bot.
```

**유튜브가 GitHub Actions 러너의 IP를 봇으로 보고 막는다.** 영상 문제가 아니다 —
실측으로 확인했다:

| 대상 | 결과 |
|---|---|
| ILLIT ‘It's Me’ MV | 봇 차단 |
| 빅벅버니(Creative Commons, 저작권 자유) | **똑같이 봇 차단** |

즉 **어떤 영상이든 막힌다.** 클라이언트 5종(기본·web_safari·mweb·tv_simply·android_vr)을
차례로 시도하도록 고쳤고, JS 런타임(deno)과 PO 토큰 공급자도 붙였지만 그것만으로는 안 뚫렸다.
다시 눌러도 결과는 같다(일시적 장애가 아니다).

## 두 레포 다 같은 상태 (260803 실측)

| | Threads·인스타·틱톡·X | 유튜브 |
|---|---|---|
| **yeulmaru-promo** (링크 자료수집) | ✅ | ❌ 봇 차단 |
| **nomute-editor** (다운로드 영상) | ✅ (실측 성공 다수) | ❌ 봇 차단 — **완전히 같은 에러** |
| **운영자 PC (Downloader.bat)** | ✅ | ✅ **집 IP라 안 막힌다** |

즉 「노뮤트에선 되는데 예울마루만 안 되는」 게 아니다. **서버(GitHub)에서 돌면 둘 다 유튜브만 막히고,
PC에서 돌면 둘 다 된다.** 지금 당장 유튜브를 받아야 하면 **Downloader.bat 을 쓰는 게 가장 빠르다.**

## 푸는 방법 — 쿠키 1회 등록 (5분, 한 번만)

유튜브에 **로그인한 상태의 쿠키**를 리포 시크릿에 넣어두면 러너가 「사람의 브라우저」로 인정받는다.
배선은 이미 끝나 있어서 **시크릿만 채우면 그 다음부터 자동**이다.

### 1. 쿠키 파일 — 이미 갖고 있다

PC 다운로더가 쓰는 파일이 그대로 정답이다:

```
OneDrive → 황도현 → 6. Nomute → 창고 → 05. Utility → yt-dlp → cookies.txt
```

이게 없거나 오래됐으면 새로 뽑는다:
1. 크롬/엣지에 확장 **「Get cookies.txt LOCALLY」** 설치 (*LOCALLY* 붙은 것 — 서버로 안 보내는 판)
2. **시크릿 창**으로 youtube.com 로그인 → 확장 아이콘 → **Export**
   (시크릿 창을 쓰는 이유 = 평소 창에서 뽑으면 나중에 그 창에서 로그아웃할 때 쿠키가 같이 죽는다)
3. **그 시크릿 창은 닫지 말고 그대로 둔다**(닫으면 세션이 끝나 쿠키가 무효)

### 2. 리포 시크릿에 넣기 — **두 곳 다**

각 주소로 들어가 **New repository secret** → Name `YT_COOKIES` → **Secret 칸에 파일 전체를 그대로** → Add secret

**「전체」가 진짜 전체다** — 맨 위 `# Netscape HTTP Cookie File` 주석 3줄부터 마지막 줄까지. 고르거나 지우지 않는다.

⚠ **함정 2개(260804 실측 — 둘 다 직접 돌려서 확인했다)**

| 하면 | 결과 |
|---|---|
| 그대로 전체 붙여넣기 | ✅ 쿠키 11개 인식 |
| 맨 위 `#` 주석 3줄을 지움 | ❌ `does not look like a Netscape format cookies file` — **첫 줄이 형식 판별표라 지우면 통째로 거부**된다 |
| **채팅·웹에서 복사**(탭이 공백으로 바뀜) | ❌ **쿠키 0개** — 그런데 **에러가 안 난다**. 경고만 뜨고 조용히 0개로 로드돼 「쿠키를 넣었는데 여전히 봇 차단」으로 보인다 |

→ 반드시 **`cookies.txt` 파일을 메모장으로 열어** Ctrl+A → Ctrl+C 로 복사한다(이 형식은 **탭 구분**이라 탭이 살아야 한다).

- https://github.com/muteno/yeulmaru-promo/settings/secrets/actions
- https://github.com/muteno/nomute-editor/settings/secrets/actions

### ⚠ 3. 그 계정이 SABR 실험에 걸려 있으면 — 다른 계정으로 (260804 실측)

쿠키를 제대로 넣었는데도 안 될 수 있다. 260804 실측이 그랬다:

```
[debug] JS runtimes: deno-2.9.4                            ← 정상
[debug] [youtube] [pot] PO Token Providers: … (external)   ← 정상
쿠키로 봇 벽도 넘음                                          ← 정상
WARNING: YouTube may have enabled the SABR-only streaming experiment for your account
ERROR:  Requested format is not available
```

**SABR = 유튜브가 계정 단위로 거는 새 전송방식 실험**이다. 걸린 계정은 서버에서 영상 트랙 주소를
아예 안 받는다(yt-dlp 미지원 · 공개 이슈 #12482). 클라이언트 6종(tv·ios·기본·mweb·web_safari·
android_vr)을 다 태워도 같았다 = **회피 불가**.

→ **다른 유튜브 계정**(새로 만든 부계정 권장)으로 로그인해 쿠키를 다시 뽑아 넣으면 된다.
   새 계정일수록 실험 편입 확률이 낮다. 배선은 그대로라 시크릿 값만 갈아끼우면 끝.

앱 화면에도 이 사유가 그대로 뜬다 — 「유튜브가 이 계정에 새 전송방식(SABR) 실험을 걸어
서버가 영상을 못 받아요 — 다른 유튜브 계정 쿠키로 바꾸면 풀려요」.

### 4. 확인

앱에서 유튜브 주소 → [저장]. (또는 Actions 탭 → 워크플로 → Run workflow)

### ⚠ 화질 주의 — 그래서 쿠키는 「먼저」 안 쓴다

Downloader.bat v6.2가 실측한 것: **--cookies 를 주면 유튜브가 최고화질 판을 안 준다**
(yt-dlp가 '로그인 세션'으로 판단해 플레이어 클라이언트가 바뀐다).
그래서 두 레포 모두 **무쿠키로 먼저 시도하고, 실패했을 때만 쿠키로 재시도**한다.
= 쿠키를 넣어도 평소 화질은 그대로다.

## 주의

- 쿠키 = **로그인 자격**이다. 시크릿에 넣으면 GitHub이 암호화해 보관하고 로그에도 안 찍히지만,
  그래도 **주 계정 말고 별도 유튜브 계정**을 쓰는 걸 권한다.
- 쿠키는 몇 주~몇 달 뒤 만료된다. 다시 봇 차단 문구가 뜨면 위 1~2를 다시 하면 된다.
- 쿠키를 빼려면 그냥 시크릿을 삭제하면 된다 — 워크플로는 시크릿이 없어도 그대로 돈다(없으면 종전처럼 시도만 한다).

## 참고 — 실패 사유는 이제 화면에 그대로 뜬다

앱이 러너의 실제 에러를 읽어 사람 말로 옮긴다(봇 차단 · DRM · 연령 제한 · 비공개/삭제 ·
용량 상한 · 없는 화질 · 진행 중 라이브). 모르는 사유는 지어내지 않고 원문 앞부분을 그대로 보여준다.
실패한 변환의 `err.txt`에는 진단 줄(JS 런타임·PO 토큰 공급자가 실제로 켜졌는지)도 함께 실린다.
