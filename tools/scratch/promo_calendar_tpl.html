⚠ 다만 10/22 곡목·출연은 여전히 미확인이라 「바흐」·「하이든」 같은 구체 작곡가 이름은 콘텐츠에 쓰지 않았다 — 공식 제목이 말하는 범위까지만 썼다. 조재혁 여수 곡목이 서울(9/11 모차르트 소나타 4곡)과 같은지도 미확인.

05 어떻게 넣나 — 이 세션은 시트에 못 쓴다

세션이 대신 못 눌러주는 이유 (변명이 아니라 설계다)

시트 데이터는 앱 모달/Worker API로만 바꾼다는 게 이 레포의 하드 룰이고 (CLAUDE.md 「데이터 안전」 · docs/앱지침.md 「두 갈래 흐름 — 섞으면 데이터 손상」), Worker 쓰기에는 담당자 PIN(X-App-Password)이 필요한데 이 세션엔 자격증명이 없다(docs/KEYS.md = 이름·위치만, 값 없음). 있어도 남의 계정으로 운영 데이터를 쓰는 건 이 자리에서 할 일이 아니다.
→ 그래서 「값 확정 + 검증」까지는 여기서 끝내고, 마지막 「보내기」만 본인 세션에서 누르는 구조로 만들었다. 아래 경로 A가 그 한 번이다(붙여넣기 → 검증 확인 → DRY=false).

경로 A — 콘솔 스크립트 (권장 · 22건 한 번에)

앱 자체 함수(_validateScheduleChange · _buildRecRow · api)를 그대로 호출한다 — 위저드가 타는 경로(Worker → Graph → SharePoint)와 완전히 같고, 새 저장 경로를 만들지 않는다. 인증도 지금 로그인한 본인 세션(password + subAdminPin)을 쓴다.

  1. 앱에 로그인한 탭에서 F12 → Console
  2. 아래 [복사] → 콘솔에 붙여넣고 Enter → 검증 표가 뜨고 「22건을 지금 등록할까요?」 팝업 → [확인] → 등록 + 캘린더 자동 갱신

[취소]를 누르면 아무것도 저장되지 않는다 — 검증만 보고 물러날 수 있다. 그 팝업이 사람이 누르는 유일한 발화점이다.

⚠ 두 번 [확인]하면 두 번 들어간다

등록 자체에 중복 차단은 없다(팝업이 「같은 프로그램·제목이 이미 N건 있다」고 알려주기만 한다). 중간에 실패하면 그 자리에서 멈추고 「앞의 N건은 이미 등록됐다」를 찍으므로, 고쳐서 다시 돌릴 땐 이미 들어간 N건을 E 배열에서 지우고 실행할 것.

⚠ 하나 남은 변수 — 접수월 설정 라이브 값 미확인

06 배치를 이렇게 짠 이유

  • 8/8(토)를 새로 넣었다 — 「토요일 가능」이 열리면서 조재혁 조기예매 25% 마감 당일에 마지막 푸시가 가능해졌다. 마감 당일 카톡은 전환이 가장 높은 자리인데, 토요일이 막혀 있었으면 D-1(금)에서 끊겼을 건이다.
  • 티켓오픈일은 카톡(11시) + 인스타(14~15시) 2단 — 카톡은 밀어내는 채널, 인스타는 남는 채널이라 역할이 다르다. 담당자도 갈려서(황세웅/심희은) 시간 충돌이 없다.
  • 카톡은 전건 11:00, 인스타는 14:00~16:00에 몰았다 — 지시 범위 안에서 기존 이력의 실제 발송 시각 분포(카톡 14:00 8건·11:00 4건 / 인스타 16:00 11건·15:00 7건)와 겹치는 구간이다.
  • 블로그는 공연 2~3주 전(9/24·10/8·10/21) — 검색 유입은 즉시 전환이 아니라 축적이라 릴스·카드보다 먼저 깔아둔다.
  • 월요일 건은 전부 뺐다 — 원래 초안의 8/10(월) 「〈그날들〉 인사영상 컨택」은 사내 업무라 홍보 게시물이 아니고, 월요일은 접수도 막힌다. 캘린더 대신 업무 일정으로 잡을 것.
  • 전략서 초안 대비 4건 늘었다(18 → {{N}}) — 티켓오픈 3건을 카톡·인스타 2단으로 쪼개고, 8/8(토) 마감 푸시를 더한 결과.
