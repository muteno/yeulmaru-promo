## 1. 임무

GS칼텍스 예울마루(여수 문화예술공원)의 **사업·홍보 조회 대시보드**를 만든다.

- **데이터 = 첨부한 `예울마루_데이터.json`이 전부.** 창작·추정·보충 금지. 없으면 "데이터 없음" 표기.
- **진입 = PIN 게이트 한 장.** 첫 화면에 "예울마루" 타이틀 + 4칸 PIN 입력. **`0510`** 입력 시 통과. 틀리면 카드 흔들림 + 빨강 안내("PIN이 올바르지 않습니다") 후 초기화.
  **팀즈/Microsoft 로그인·계정 선택·아이디·비밀번호 단계는 절대 만들지 마라.**

- 모든 UI 텍스트 **한국어**.

## 2. 데이터 (첨부 JSON 구조 — 그대로 쓰면 된다)

```
{
  meta: { expectedCounts, recordsStatusDistribution, fieldNotes, … }   // 검증·설명용
  records:      [ … ]   // 137건 — 홍보 신청내역 = 캘린더 원본
  programs:     [ … ]   //  30건 — 프로그램 마스터
  special:      [ … ]   //  34건 — 담당자 특별일정
  opsMaster:    [ … ]   //   9건 — 공연 사업 마스터  (ID)
  opsDaily:     [ … ]   //1477건 — 공연 일일 판매실적 (공연ID → opsMaster.ID)
  exhibMaster:  [ … ]   //  25건 — 전시 마스터        (전시ID)
  exhibDaily:   [ … ]   //  11건 — 전시 일일실적      (전시ID → exhibMaster.전시ID)
  platforms:    [ … ]   //  10건 — 홍보 플랫폼 3단 분류(라벨)
  contents:     [ … ]   //   5건 — 구분·형식·상태 값 목록(필터)
  applySettings:{ … }   //   6키 — 홍보 접수 설정
}
```

**이 JSON은 이미 정규화돼 있다 — 추가 변환하지 마라:**
- 모든 날짜 = `"2026-05-23"` 형식 문자열. **엑셀 시리얼 변환 코드를 넣지 마라**(이미 변환 완료).
- 수량·금액·점유율 = JSON number(빈칸은 `null`).
- 개인정보(PIN·비밀번호·이메일·전화·내선) 열은 **애초에 없다**.
- 빈 행 제거 완료 — 이 행수가 실서버와 동일하다.

## 4. 화면 (상단 내비 1줄 "예울마루" + 메뉴 3개)

### ① 홍보 캘린더 (기본 화면)
- 월간 그리드. `records`의 각 건을 `날짜`별 뱃지로 배치.
- 뱃지 텍스트 = `콘텐츠 제목`(없으면 `프로그램`). 뱃지 색 = `진행 상태`:
  완료 `#1A6B3C` / 취소·반려 `#E24B4A` / 신청 중·보류 `#D88455` / 예정·승인 `#4A4DE7` (연한 배경 + 진한 글자).
- `special`은 회색 계열 뱃지로 병기(유형: 교육·휴가·출장·회의·영상 제작 등).
- 뱃지 클릭 → 상세 모달(주요 필드 표). 오늘 셀 강조. 월 이동 ‹ ›.
- **데이터가 2026년 5~7월에 몰려 있다** — 첫 화면은 데이터가 보이는 달로 열어라.

### ② 프로그램
- `programs` 카드: `풀네임`, 기간(`시작일`~`종료일`), `장소`, `담당자`, `콘텐츠구분`, `URL`(있으면 링크).
- 판매중(오늘이 `판매시작일`~`판매종료일`) 배지. `콘텐츠구분` 필터 칩(공연·전시·예술교육).

### ③ 사업 실적
- **공연**: `opsMaster` 목록 → 선택 시 `opsDaily`(`공연ID` = `ID` 조인)로 일일 추이 라인차트 + 누계 KPI(유료좌석·유료금액·점유율).
- **전시**: `exhibMaster` 표(목표관객·목표금액·최종실적·최종점유율) + `exhibDaily`(있는 전시만).
- ⚠️ **점유율 = 목표 달성률**(100% 초과 가능). "좌석 점유율"이라고 쓰지 마라.
- 차트 색 = §3 카테고리 6색 순서. 단일 시리즈는 `#4A4DE7`.

## 5. 데이터 해석 규칙 (함정 — 실제 사고 전례)

1. **신청자 ≠ 게시 담당자**: `records.신청자`가 신청 본인이다. "누가 신청했나"는 전부 `신청자` 기준. `게시 담당자`는 지정값("상관 없음" 가능)이라 표시 주체로 쓰지 마라.
2. `records.진행 상태` 값: 신청 중 · 예정 · 완료 · 보류 · 취소 · 반려 · **임시**(임시저장 — **화면에 표시하지 마라**).
3. 홍보 노출 기간 = `programs.홍보시작일` ~ `판매종료일`(비면 `종료일`). "홍보종료일" 개념은 없다 — 만들지 마라.
4. `null`·빈 문자열 = 값 없음. 0과 구분해서 "—"로 표기.
5. `programs.프로그램ID`·`opsDaily.공연ID`·`exhibMaster.전시ID`는 `260514_01` 형태 **문자열**이다(숫자로 바꾸지 마라).
