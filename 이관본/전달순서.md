# MISO 전달 순서 — 처음부터 다시 할 때 (이 순서 그대로)

> 전제: MISO 플레이메이커(대화형 빌더, React 19 + Vite + Tailwind 4 + shadcn/ui 환경) · 파일 첨부 가능
> 준비물은 **2개뿐**이다. 나머지 문서는 참고용이므로 전달하지 않는다.

## 준비물 (딱 2개)

| # | 파일 | 크기 | 받는 곳 |
|---|---|---|---|
| 1 | `MISO_전달_통합본.md` (명세) | 8KB | `https://promo.yeulmaru.org/이관본/MISO_전달_통합본.md` |
| 2 | `첨부/예울마루_데이터.json` (전 데이터) | 691KB | `https://promo.yeulmaru.org/이관본/첨부/예울마루_데이터.json` |

⚠️ **다른 문서는 같이 첨부하지 마라.** 특히 `빌드명세.md`·`standalone.html`을 함께 주면
수신 LLM이 어느 걸 따를지 헷갈려 재구현으로 새거나 컨텍스트가 터진다.

## 1단계 — 새 앱 생성 후 첫 메시지

파일 2개를 첨부하고, 아래 한 덩어리를 그대로 붙여넣는다.

```
첨부한 파일 2개로 사내 조회용 대시보드를 만들어줘.

- MISO_전달_통합본.md = 만들 것의 명세다. 이 문서를 그대로 따라라.
- 예울마루_데이터.json = 데이터 전부다. 이 안에 있는 것만 쓰고, 데이터를 창작하지 마라.

특히 이 3가지는 반드시 지켜라:
1. 첫 화면은 4칸 PIN 입력이고 0510으로만 통과한다. 팀즈/Microsoft 로그인은 절대 만들지 마라.
2. JSON의 날짜는 이미 "2026-05-23" 형식으로 정규화돼 있다. 엑셀 시리얼 변환 코드를 넣지 마라.
3. 색은 명세 §3 팔레트만 쓴다. 새 색을 만들지 마라.

완성되면 로드된 실제 건수(records / programs / special / opsDaily)와 접속 URL을 알려줘.
```

## 2단계 — 결과 검증 (이 숫자가 나와야 정상)

빌더가 보고한 건수를 이 표와 대조한다. 하나라도 다르면 3단계로.

| 데이터 | 기대 건수 |
|---|---|
| records (홍보 신청내역) | **137** — 완료 89 · 취소 31 · 예정 12 · 보류 5 |
| programs / special / opsMaster | 30 / 34 / 9 |
| opsDaily / exhibMaster / exhibDaily | 1477 / 25 / 11 |

**눈으로 볼 것 4가지**
1. 첫 화면 = PIN 4칸 (팀즈 로그인 화면이 뜨면 실패)
2. `0510` 입력 → 대시보드 진입
3. 캘린더를 **2026년 5·6·7월**로 이동 → 뱃지가 실제로 보임 (데이터가 이 구간에 몰려 있음)
4. 색이 인디고(`#4A4DE7`)·살몬(`#D88455`) 톤 — 초록/파랑 같은 낯선 색이 섞였으면 팔레트 위반

## 3단계 — 어긋났을 때 보정 (증상별 한 줄 지시)

| 증상 | 붙여넣을 지시 |
|---|---|
| 캘린더가 비어 있다 | `records가 137건 로드됐는지 확인해라. 0건이면 첨부 JSON의 records 배열을 다시 읽어라. 캘린더 첫 화면을 2026년 6월로 열어라.` |
| 건수가 137이 아니다 | `첨부 JSON의 meta.expectedCounts와 실제 로드 건수를 대조해 보고해라. 다르면 파싱을 고쳐라 — JSON은 이미 정제됐으니 필터를 잘못 넣은 것이다.` |
| 팀즈/로그인 화면이 뜬다 | `인증 관련 코드를 전부 제거하고, 첫 화면을 4칸 PIN 입력만 남겨라. 0510이면 통과, 아니면 에러 표시.` |
| 날짜가 1970년·숫자로 나온다 | `JSON의 날짜는 이미 "2026-05-23" 문자열이다. 엑셀 시리얼 변환 로직을 제거하고 문자열을 그대로 파싱해라.` |
| 색이 이상하다 | `명세 §3 팔레트 표의 색만 사용하도록 index.css를 다시 써라. 표에 없는 색은 전부 제거.` |
| 점유율이 "좌석 점유율"로 표기 | `점유율은 목표 달성률이다(100% 초과 가능). 라벨을 "목표 달성률"로 바꿔라.` |
| 저장/등록 버튼이 생겼다 | `쓰기 기능(등록·수정·삭제)은 범위 밖이다. 관련 UI를 전부 제거하고 조회·검색·필터만 남겨라.` |

## 4단계 — 발행(배포)

화면이 맞으면 우상단 **발행하기**로 배포하고 URL을 확보한다.
배포 후 화면이 깨지면 `이관본/현장실행킷.md` §1.5의 **콘솔 진단 카드**(F12 → Console 1줄)를 실행해
결과를 캡처해서 원격(Claude)에 전달한다.

## 참고 — 이 순서에 쓰지 않는 파일들 (용도만 기억)

| 파일 | 언제 쓰나 |
|---|---|
| `첨부/*.csv` (10종) | 빌더가 JSON을 못 읽거나, 특정 데이터셋만 따로 줄 때 |
| `standalone.html` (3.85MB) | **정적 HTML 호스팅 자리가 생겼을 때만** — 원본 앱 통짜 이식판(완전 동일 동작). 플레이메이커 채팅에는 부적합(용량·코드생성형 환경) |
| `빌드명세.md` | 구 버전 명세(폴백). `MISO_전달_통합본.md`가 이걸 대체함 |
| `현장실행킷.md` | 분기 결정트리·콘솔 진단·Worker API 계약·MISO 키 치환표 |
| `miso_db.json` (3.0MB) | 26데이터셋 전량(규정·로그·메시지·교육기관 포함) — 에이전트 지식베이스용 |
| `비공개/` | 회원 DB 반입 패키지(29,752행) — MISO 내부 DB에 직접 업로드, 공개 금지 |

```bash
node tools/miso/build_single_json.mjs       # → 이관본/첨부/예울마루_데이터.json  ← 이것만 다시 첨부
```
