# 3차 보강 지시 — 인트로(PIN 화면) 「동그라미」를 원본과 똑같이 고쳐라

> 첨부: 이 문서 하나로 끝난다(데이터 파일 불필요 — 이 화면은 데이터를 안 쓴다).
> **대상은 인트로 화면 하나뿐이다.** 대시보드·캘린더·프로그램 화면은 **절대 건드리지 마라.**
> 2차 보강(판매현황·차트)은 그대로 유지한다.

## 0. 결론 한 줄

지금 만든 PIN 칸은 **네모난 박스 4개 안에 작은 점**이 들어있다.
원본은 **박스가 없다.** 투명한 자리(42×48px) 한가운데에 **지름 15px 동그라미 1개**만 떠 있다.

┌────┐ ┌────┐ ┌────┐ ┌────┐          ●     ●     ●     ○
│ ●  │ │ ●  │ │ ●  │ │    │       (테두리·배경 없음. 동그라미만)

```

## 2. ⛔ 절대 하지 마라 (지금 잘못 쓰고 있는 것)

1. **shadcn `<Input>` · `<InputOTP>` · `<PinInput>` 같은 기성 컴포넌트를 쓰지 마라.**
   그 컴포넌트들이 박스 테두리·배경·포커스 링을 자동으로 붙여서 지금 모양이 됐다.
   아래 4절의 **순수 `<input class="pin">` + `::before` 동그라미** 구조를 그대로 써라.
2. **Tailwind 유틸리티 클래스로 이 화면을 만들지 마라.** (`border rounded-md bg-white` 같은 것)
   아래 5절 CSS를 **글로벌 CSS 파일(`src/index.css` 등)에 통째로 붙여넣고**, 클래스명만 그대로 쓴다.
   Tailwind 4의 `@theme`·preflight가 `input`의 `border`/`background`를 건드리면 CSS 쪽에 이미 `border:none;background:transparent`가 있으니 그대로 두면 된다.
3. **숫자를 화면에 보이게 하지 마라.** input은 `type="password"`이고 `color:transparent`·`caret-color:transparent`다.
   즉 **점(•)도, 숫자도 input에서는 안 보인다.** 보이는 건 오직 `::before` 동그라미다.
4. **확인 버튼을 만들지 마라.** 4번째 숫자 입력 = 즉시 제출.
5. **테두리·그림자를 슬롯에 붙이지 마라.** `.pin-slot`은 완전 투명하다. 그림자는 `.pin-wrap`에만 있다.
6. **색을 새로 만들지 마라.** 이 화면에 쓰는 색은 아래 6개뿐이다.

| 이름 | 값 | 쓰이는 곳 |
|---|---|---|
| 강조(인디고) | `#4A4DE7` | 채운 동그라미, 안내 문구, 첫 칸 힌트 링, YEULMARU 글자 |
| 성공(초록) | `#1A6B3C` | 성공 링 |
| 에러(빨강) | `#E24B4A` | 틀렸을 때 동그라미 테두리, 에러 문구 |
| 잉크(글자) | `#1A1A2E` | 로고 글자 |
| 흐린회색 | `#bbb` | 빈 동그라미 테두리, "계정 다시 선택" 글자 |
| 살몬 | `#D88455` | 계정명(`#pin-account`) |

## 6. JS 동작 — 이대로 구현해라

### 6-1. 상태 3종

| 클래스 | 언제 | 화면 |
|---|---|---|
| `.lit` | 숫자를 넣은 **직후 0.3초** | 동그라미가 인디고로 차면서 "통" 튄다 |
| `.filled` | 0.3초 뒤 정착 | 인디고로 꽉 찬 동그라미 (모션 없음) |
| `.err` | PIN 틀림 | 동그라미 테두리만 빨강(`#E24B4A`), 안은 빈 상태 |

### 6-2. 입력 핸들러 (원본 로직 그대로)

```js
const pins = document.querySelectorAll('.pin');   // 4개

pins.forEach((el, i) => {
  const _fill = () => { el.type='password'; el.classList.remove('lit'); el.classList.add('filled'); };

  el.addEventListener('input', () => {
    el.classList.remove('err');
    _pinFirstHintStop();      // 입력 시작 = 첫 칸 안내 링 중지
    _pinHintUpdate();         // 안내 문구 갱신

    if (el.value) {
      el.type = 'password';
      el.classList.add('lit'); el.classList.remove('filled');
      clearTimeout(el._at);
      el._at = setTimeout(_fill, 300);          // 0.3초 뒤 팝 종료 → filled 정착
    } else {
      el.type = 'password';
      el.classList.remove('lit', 'filled');
      clearTimeout(el._at);
    }

    if (el.value.length === 1 && i < 3) pins[i+1].focus();   // 다음 칸으로
    if (i === 3 && el.value.length === 1) tryLogin();        // ★ 자동 제출 (확인 버튼 없음)
  });

  el.addEventListener('keyup', () => { if (el.value.length===1 && i<3) pins[i+1].focus(); });
  el.addEventListener('keydown', e => { if (e.key==='Backspace' && !el.value && i>0) pins[i-1].focus(); });

  // 빈 칸 건너뛴 입력 방지 — 뒤→앞(k<i)만 이동시킨다(양방향이면 Backspace와 핑퐁 충돌)
  el.addEventListener('focus', () => {
    const k = Array.from(pins).findIndex(p => !p.value);
    if (k > -1 && k < i) pins[k].focus();
  });

<details>
<summary>셰이더 소스 (그대로 복사)</summary>

정점 셰이더:
```glsl
#version 300 es
in vec2 p; out vec2 v_objectUV; uniform vec2 u_res;
void main(){ gl_Position=vec4(p,0.,1.); vec2 uv=p*0.5; uv.x*=u_res.x/max(1.,u_res.y); v_objectUV=uv; }
```

프래그먼트 셰이더:
```glsl
#version 300 es
precision mediump float;
uniform float u_time; uniform highp vec2 u_res;
uniform vec4 u_colors[10]; uniform float u_colorsCount;
uniform float u_distortion; uniform float u_swirl;
uniform vec4 u_card; uniform float u_grooves; uniform float u_refract; uniform float u_flShadow; uniform float u_flHi;
in vec2 v_objectUV; out vec4 fragColor;
vec2 rotate(vec2 uv,float th){ return mat2(cos(th),sin(th),-sin(th),cos(th))*uv; }
vec2 getPosition(int i,float t){ float a=float(i)*.37; float b=.6+fract(float(i)/3.)*.9; float c=.8+fract(float(i+1)/4.); return .5+.5*vec2(sin(t*b+a),cos(t*c+a*1.5)); }
vec3 meshBG(vec2 uv0){
  vec2 uv=uv0+.5; float t=.5*(u_time+41.5);
  float radius=smoothstep(0.,1.,length(uv-.5)); float center=1.-radius;
  for(float i=1.;i<=2.;i++){
    uv.x+=u_distortion*center/i*sin(t+i*.4*smoothstep(.0,1.,uv.y))*cos(.2*t+i*2.4*smoothstep(.0,1.,uv.y));
    uv.y+=u_distortion*center/i*cos(t+i*2.*smoothstep(.0,1.,uv.x));
  }
  vec2 uvR=uv-.5; uvR=rotate(uvR,-3.*u_swirl*radius); uvR+=.5;
  vec3 color=vec3(0.); float tw=0.;
  for(int i=0;i<10;i++){
    if(i>=int(u_colorsCount))break;
    vec2 pos=getPosition(i,t); vec3 cf=u_colors[i].rgb*u_colors[i].a;
    float dist=pow(length(uvR-pos),3.5); float w=1./(dist+1e-3);
    color+=cf*w; tw+=w;
  }
  return color/max(1e-4,tw);
}
void main(){
  vec2 suv=gl_FragCoord.xy/u_res;
  float hasCard=step(0.0001,u_card.z-u_card.x);
  float inCard=hasCard*step(u_card.x,suv.x)*step(suv.x,u_card.z)*step(u_card.y,suv.y)*step(suv.y,u_card.w);
  float cw=max(1e-4,u_card.z-u_card.x);
  float lx=(suv.x-u_card.x)/cw;
  float gpos=lx*u_grooves; float gf=fract(gpos)-0.5;
  float asp=u_res.x/max(1.,u_res.y);
  float grooveWobj=(cw*asp)/max(1.,u_grooves);
  float refr=gf*u_refract*grooveWobj;
  vec2 uvS=v_objectUV; uvS.x+=refr*inCard;
  vec3 color=meshBG(uvS);
  float edge=abs(gf)*2.;
  float shadow=pow(edge,1.7);
  float hi=smoothstep(0.85,1.0,edge);
  color=mix(color,color*0.58,shadow*inCard*u_flShadow);
  color+=hi*inCard*u_flHi*0.5;
  fragColor=vec4(color,1.0);
}
```

배선 요령:
- 삼각형 1개(`[-1,-1, 3,-1, -1,3]`)를 `TRIANGLES`로 그린다.
- 매 프레임 `u_time = (performance.now()-t0)/1000`, `u_res = [캔버스 픽셀 폭, 높이]`.
- `u_card` = `.login-card`의 `getBoundingClientRect()`를 0~1 화면좌표로 정규화한 `[x0, y0, x1, y1]`
  (**y는 아래가 0** — WebGL 좌표계이므로 `1 - bottom/H`, `1 - top/H` 순서로 넣어라). 카드 뒤에만 세로 홈 굴절이 생긴다.
- `#login`이 `display:none`이 되면 `cancelAnimationFrame`으로 멈춘다(앱 사용 중 연산 0).
- `webglcontextlost` 이벤트에서 GL을 버리고 다음 시작 때 재생성한다.
- **WebGL2 미지원이면 캔버스를 그냥 비워라** → 흰 배경 폴백. 깨지지 않는다.
```

## 10. 참고 — 왜 이렇게 만들었나 (설계 의도)

이걸 알면 세부 판단이 흔들리지 않는다.

1. **동그라미와 숫자를 물리적으로 분리했다.**
   과거에 하나의 박스 안에 숫자와 점을 같이 두니 겹쳐 보였다.
   그래서 **동그라미는 `::before`(부모 슬롯의 가상요소), 숫자는 투명 input** 으로 층을 나눴다.
   → input에 테두리·배경을 절대 주면 안 되는 이유가 이것이다.
2. **숫자는 끝까지 안 보인다.** `type=password` + `color:transparent` 이중 마스킹.
   대신 "쓰는 느낌"은 동그라미가 **0.34초 통 튀는 팝**으로 담당한다.
3. **첫 칸 안내 링은 "컴맹 배려"용이다.** 어디에 커서가 있는지 모르는 사용자를 위해
   입력 전까지 첫 칸을 인디고 링이 돈다. 첫 글자를 넣는 순간 즉시 멈춘다.
4. **성공 링은 초록이고 순차다.** 4칸이 동시에 그려지면 "체크됐다"는 느낌이 약하다.
   0.1초씩 밀어 왼→오른쪽으로 훑는 리듬을 만든다.
5. **확인 버튼이 없는 것은 의도다.** 4자리를 다 넣으면 더 확인할 게 없다.
   버튼을 만들면 클릭 한 번이 늘고, 원본 사용자들이 "왜 안 들어가지" 하고 멈춘다.
