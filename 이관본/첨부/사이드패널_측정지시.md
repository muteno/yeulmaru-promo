# 크롬 사이드패널 Claude에게 시킬 측정 지시 (읽기 전용 · 크레딧 0)

> **언제** = MISO Playmaker가 빌드를 끝낸 직후, preview 화면이 PIN 게이트에 있을 때
> **왜 이렇게 시키나** = v5 빌드는 자체 검증에서 "투명 컨테이너 확인"으로 **통과 판정했는데 화면엔 네모 박스가 있었다.**
> 그래서 이 지시서는 **기대값을 일부러 알려주지 않는다.** 판정은 원본 정본을 가진 쪽(깃 세션)이 한다.
> 사이드패널이 할 일은 **날값을 정확히 뜨는 것뿐**이다.

---

## 아래를 그대로 복사해서 사이드패널에 붙여넣어라

---

너는 지금 이 탭에 열려 있는 MISO preview의 **PIN 입력 화면을 측정**한다.

### ⛔ 절대 하지 말 것
1. **코드를 고치지 마라.** 파일 수정·저장·빌드·발행 전부 금지.
2. **값이 맞았는지 틀렸는지 판정하지 마라.** 기대값을 모르는 상태로 **날값만** 보고해라. "정상입니다"·"일치합니다" 같은 말을 쓰지 마라.
3. **추측으로 채우지 마라.** 못 뽑은 값은 `"측정실패"` 라고 적어라.
4. MISO 채팅창(왼쪽)에 아무것도 입력하지 마라.

### 2단계 — 5개 상태에서 각각 실행

**순서를 지켜라.** 각 단계에서 나온 JSON을 전부 모아둔다.

| # | 화면 상태 만들기 | 실행할 명령 |
|---|---|---|
| 1 | 아무것도 안 누른 처음 상태 (새로고침 직후) | `YM("빈칸")` |
| 2 | 첫 칸에 `0` 한 글자만 입력하고 **0.2초 안에** | `YM("입력직후")` |
| 3 | 그 상태에서 **1초 더 기다린 뒤** | `YM("입력정착")` |
| 4 | 전부 지우고 `1234` 입력(틀린 PIN) | `YM("실패")` |
| 5 | 전부 지우고 `0510` 입력 → **링이 그려지는 동안(0.3초 안에)** | `YM("성공")` |

> 5번에서 앱 화면으로 넘어가버리면, 새로고침해서 PIN 화면으로 돌아온 뒤 다시 시도해라.
> 링을 못 잡으면 `YM("성공")`을 `setTimeout(()=>YM("성공"),150)` 으로 감싸서 실행해라.

### 이 측정으로 깃 세션이 판정하는 것

| 뽑은 값 | 무엇을 가른다 |
|---|---|
| `클래스원문.slot` 에 `rounded-*`·`border`·`bg-*`·`shadow-*` 유무 | 네모 박스가 **JSX Tailwind에서 오나 CSS에서 오나** — 고칠 파일이 갈린다 |
| `슬롯_before.content` = `none` 인지 | 빈 동그라미가 **아예 안 만들어지는지** (v5의 진짜 원인 후보 1번) |
| `슬롯_before.width` / `borderRadius` | 동그라미 크기·모양 |
| `슬롯.backgroundColor`/`border`/`borderRadius` | 박스가 남아 있는지 |
| `슬롯좌표` 의 x 간격 | 슬롯 폭 + gap (v5는 49px = 정본 일치) |
| `링.실제크기` · `링_circle.r속성` | 힌트 링이 과대한지 |
| `링_circle.stroke`/`strokeWidth`/`animationName` | 성공·힌트 링 배선 여부 |
| `카드.backdropFilter` | 유리 효과 적용 여부 (v5 미확인 항목) |
| `배경.canvas있나`/`webgl2`/`canvas불투명도` | 움직이는 mesh 배경 여부 (v5 미확인 항목) |
| `버튼전체` | 「확인」 제거 · 「계정 다시 선택」 존재 |
| `입력직후` vs `입력정착` 의 `animationName` 차이 | `pinDotPop` 팝 모션 작동 여부 |
| `pin_slot룰있나` · `스타일시트` | 정본 CSS가 실제로 로드됐는지 |
| `에러` | 렌더 중 JS 에러 |

### 왜 기대값을 안 주나
v5에서 Playmaker가 *"인디고 점 + 투명 컨테이너 확인"* 으로 자체 검증을 통과시켰는데 실제로는 박스가 있었다.
기대값을 아는 검증자는 **일치를 찾으러** 간다. 날값만 뜨게 하면 그럴 여지가 없다.
