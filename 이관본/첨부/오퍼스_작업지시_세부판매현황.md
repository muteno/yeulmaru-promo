## 2. 최우선 과제 (운영자 지시: "제일 급한거")

**MISO 빌드에서 프로그램을 클릭했을 때 세부 판매현황이 나오게 한다.** 지금은 아무 일도 안 일어난다.

### 원본은 이렇게 동작한다 (내가 실렌더로 실측한 값 — 추정 아님)

**모달이 아니다.** 목록이 있던 **박스가 통째로 그 프로그램 상세로 넘어간다**(책장 넘김).

```
[기본 화면 = 사업 실적]
 우측 「판매 현황」 박스
   ├ (목록) 판매현황 표 — 그룹 머리글 ● 공연 7 / ● 전시 1 + 행 8개
   └ 행 클릭 ──────────────────────────┐
                                        ▼
   (상세) .ry-detail.mv-swipe      ← 표가 사라지고 이걸로 교체
     ├ .ry-detail-body
     │    └ .srail-card  1장   ← 그 프로그램 카드. 클릭 핸들러는 떼어냄
     └ .ry-nav
          └ .bizm-pgctl  ‹ ●●●●●●●● ›   ← 점 8개 = 표 행 수
   복귀 = 「‹ 목록」
```

### 배선 체인 (원본 코드)

| 단계 | 실제 코드 |
|---|---|
| 1 | 표 행: `class="clk"` `onclick="_railYrmPick('perf'\|'ex', <키>)"` `data-uhakey="<kind>:<키>"` |
| 2 | `_railYrmPick` → `_srailUhaKick()`(5초 자동전환 잠시 정지) + `_srailUhaShow(idx)` + **`_ryDrillOpen(want)`** |
| 3 | `_ryDrillOpen` → 진입 직전 `_ryDrillCapture()`로 **표에 보이던 DOM 순서를 캡처**(그룹·정렬·필터 반영 상태) |
| 4 | `_ryDrillHtml(p,key)` = `<div class="ry-detail"><div class="ry-detail-body">` + `_srailCard(p)` 또는 `_srailCardEx(p)` + `</div>` + `_ryDrillNav(key)` + `</div>` |
| 5 | `_ryDrillStrip(box)` → 카드의 `onclick`·`onkeydown`·`role`·`tabindex` **제거** + `cursor:default` |
| 6 | `_ryFlip(el, 1)` → `.mv-swipe` (복귀는 `.rev` 추가 = 반대 방향) |

> ⚠️ **상세 안의 카드를 또 클릭해도 아무 일이 없어야 한다.** 원본이 일부러 핸들러를 뗀다(운영자 지시 "이 안에 국한").

### 실측된 공연 상세 내용 — 위→아래 순서 그대로

`브런치 콘서트 Ⅲ <현 위로 흐르는 계절>` 행을 클릭한 결과다.

```
div.ry-detail.mv-swipe
  div.ry-detail-body
    div.srail-card
      div.srail-r1
        div.srail-name    「브런치 콘서트 Ⅲ <현 위로 흐르는 계절>」
        span.srail-dday   「D-35」
      div.srail-meta      「클래식 · 예술성 · 9.3(목) · 판매 28일차」
      div.srail-occrow
        span.srail-occcap 「점유율」
        span.srail-occ    「31.1%」
        span.srail-delta.dn 「-0.1%p」
        span.srail-seatsub  「( 288 / 926 )」   ← 288은 <b>
      div.srail-spark                            ← 최근 7일 스파크라인(SVG)
      div.srail-bar
        i                                        ← 점유율 진행 바
      div.srail-r3
        span              「288 / 926석」
        span.tgt.bad      「목표 50% -18.9%p」
      div.srail-fc        「<b>AI 예상</b> 이 추세면, 7일 뒤 예상 누적 331석 ( +43 ), 2주 뒤 예상 누적 374석 ( +86 )」
  div.ry-nav
    span.bizm-pgctl  ‹ · dots(8) · ›
```

### 실측된 전시 상세 (다른 카드다 — `_srailCardEx`)

`GS칼텍스 예울마루 기획전시 <숨: 쉬는 SUM>` 행 클릭 결과. 지표가 **좌석 점유가 아니라 목표관객 대비 달성률**이다.
정확한 구조·텍스트는 `세부판매현황_정본.md` §2 참조.

### 프로그램 넘김 (`.ry-nav`) 규칙

| 항목 | 규칙 |
|---|---|
| 부품 | 좌측 보드 페이지 넘김 `.bizm-pgctl`을 **그대로 계승** (`‹` + `.dots` + `›`) |
| 점 개수 | 표에 보이던 행 수 (실측 **8**) |
| 순서 | **표의 DOM 순서** — 그룹·정렬·필터 반영 상태. 원본 데이터 순서가 아니다 |
| 순환 | 마지막에서 `›` → 처음으로 (`((i%n)+n)%n`) |
| 접근성 | 점 = `aria-label="N번째 프로그램"` + `aria-pressed` · 화살표 = `aria-label="이전/다음 프로그램"` |
| 행 2개 미만 | 넘김 UI를 **아예 안 그린다** |

### 표 쪽에서 같이 일어나는 것 (놓치기 쉬움)

1. 선택된 행에 `.on` 클래스 (`_railYrmMarkRow`) — 5초 자동전환 때도 따라 움직인다
2. 액티브 행 하이라이트 pill이 **행 사이를 미끄러진다** (`_railYrmHlTo`)
3. 상세 진입 시 **5초 자동전환이 잠시 멈춘다**(읽는 중) → 유휴 뒤 재개
4. 복귀하면 표가 다시 그려지고 선택 행 `.on` 유지

## 3. 네가 측정할 것 (MISO 현재 상태)

너는 preview의 DOM·React 파이버·`src/**` 소스를 직접 읽을 수 있다. 아래를 확인해라.

| # | 확인 | 왜 |
|---|---|---|
| 1 | 판매현황 표 행에 클릭 핸들러가 **있나** | 없으면 신설, 있으면 왜 안 먹는지 |
| 2 | 프로그램 상세 컴포넌트가 **이미 있나** (`DetailModal.tsx` 같은 것) | 있으면 재사용, 없으면 신설. **모달로 만들어져 있으면 인라인 교체로 바꿔야 한다** |
| 3 | 표 행 데이터에 상세 렌더에 필요한 필드가 다 있나 | 점유율·판매석·오픈석·목표·D-day·판매일차·최근7일·예측 |
| 4 | 최근 7일 스파크라인 데이터가 배선돼 있나 | `opsDaily`에서 그 공연ID 최근 7일 |
| 5 | 예측(AI 예상) 계산이 있나 | 없으면 신설 필요 여부 판단 |
| 6 | `정본_스타일.css`가 로드돼 있나 | `.ry-detail`·`.srail-card`·`.bizm-pgctl` 룰 존재 확인 |
| 7 | 전시 행과 공연 행이 **다른 카드**로 갈리나 | 원본은 갈린다 |
| 8 | 런타임 에러 0인가 | 상세 진입 시 |

**측정만 하고 MISO에 빌드를 시키지 마라.** 지시서는 운영자가 붙인다.

```md
# 프로그램 클릭 → 세부 판매현황 신설

## 0. 지금 잘 된 것 (⛔ 손대지 마라)
(v8에서 이미 맞은 것들을 나열 — PIN 게이트·KPI 4칸·판매현황 표·캘린더·프로그램 30건 등)

## 1. 만들 것
(원본 구조·배선 체인·텍스트 순서를 위 §2 내용으로 옮겨 적기. 파일 경로와 코드까지)

## 2. 데이터 배선
(각 표시값이 어느 데이터셋 어느 필드에서 오는지)

## 3. CSS
(정본_스타일.css의 어느 클래스를 쓰는지. 새로 만들지 말라고 명시)

## 4. 훅 규칙 상시 준수  ← 반드시 포함
(§5 그대로)

## 5. 자체검증 N항
(실측 명령 + 기대값. "빌드 성공"만으로 통과 처리 금지)
```

## 5. 훅 규칙 — 이 블록은 매 지시서에 반드시 넣어라

네가 찾은 결함이 재발하지 않게, MISO에 보내는 모든 지시서에 이걸 붙여라.

```md
[훅 규칙 상시 준수 — 전 파일]
1. useRef/useState/useEffect/useMemo를 useMemo·useCallback·map·if·for·try
   콜백 안에서 호출하지 마라. 반드시 컴포넌트 함수 최상위에서만 호출한다.
   (ref 배열이 필요하면 useRef를 개별 변수로 선언하고 배열은 렌더 시
    [ref0,ref1,ref2,ref3]로 그냥 만든다. useMemo로 감싸지 마라.)
2. 조건부 렌더는 훅 선언을 모두 끝낸 뒤 early return으로만 한다.
3. 자체검증: pnpm exec tsc --noEmit 후, preview에서 PIN 0510을 실제로
   입력해 목표 화면까지 진입하고 console 에러 0건을 보고에 적어라.
   "빌드 성공"만으로 통과 처리하지 마라 — 이 유형은 빌드가 통과한다.
4. 상태 전이 검증 필수: 첫 렌더만 보고 판정하지 마라. 클릭·입력으로
   상태를 한 번 이상 바꾼 뒤에도 화면이 살아 있는지 확인해라.
```

4번은 네 진단에서 나온 교훈이다 — v7은 `tsc --noEmit`·`pnpm build`·정지 화면 스크린샷 8/8을 **다 통과**하고도 첫 입력에서 죽었다.

## 6. ⛔ 금지

1. **발행(publish) 하지 마라.** 관리자 승인 + 비용이 든다. 운영자는 MISO 관리자가 아니다.
2. **「AI에게 수정 요청」류 버튼을 누르지 마라.** 지난번에 v8 빌드가 돌아 크레딧이 소모됐다(앱 322→335 · 잔여 663→650).
3. **원본 정본을 추측하지 마라.** §1 URL을 열어 실물을 확인해라. 못 열면 그렇게 보고하고, 이 문서에 적힌 실측값만 써라.
4. **판정을 낙관하지 마라.** 값이 안 맞으면 안 맞는다고 적어라.
5. 새 색을 만들지 마라. 팔레트 = `#4A4DE7` · `#D88455` · `#1A6B3C` · `#E24B4A` · `#1A1A2E` · `#888` · `#bbb`.

## 7. 2순위 — 그 외 세부 기능 (여유 있으면 같이)

운영자: *"그 외로는 세부적인 기능들"*. 우선순위 순.

| 순위 | 기능 | 원본 위치 |
|---|---|---|
| 1 | **캘린더 날짜 셀 클릭 → 그날 홍보 목록** | 캘린더 셀 `.c` 클릭 → 우측 패널 |
| 2 | **프로그램 카드 클릭 → 그 프로그램 상세** | 프로그램 화면 카드 (지금 MISO는 무반응) |
| 3 | 캘린더 `+N건 더보기` 펼침 | `.c-count` |
| 4 | 좌측 보드 페이지 넘김 (연간 실적 ↔ 운영대장 현황) | `.bizm-pgctl` — 이미 부품이 있다 |
| 5 | 판매현황 표 그룹 머리글 접기/펼치기 | `.ry-grp-hd` |
| 6 | 우하단 2×2 「사업 판매현황」 5초 자동전환 | `#srail-uha` |

이건 1순위가 끝난 뒤에 손대라. **한 번에 다 넣으라고 MISO에 시키지 마라** — v7처럼 크게 건드리면 되던 것이 깨진다.

```
런타임 에러: N건 (내용)

[내가 만든 MISO 지시서]
(위 §4 형식 산출물)

[막힌 것]
(URL 못 열었다 / 소스 접근 안 된다 등 — 있으면)
```

이걸 받으면 내가 정본과 대조해서 빠진 곳을 짚어 다음 라운드를 만든다.
